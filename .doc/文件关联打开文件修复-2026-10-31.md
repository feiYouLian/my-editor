# 文件关联打开失败的修复（2026-10-31）

## 现象

在资源管理器里用「打开方式 ▸ my-editor」选择 exe 打开文件，应用起来后没有任何文件被打开（若应用已在运行，只是把窗口拉到前台）。

## 根因

1. **应用从未读取启动参数**：`lib.rs` 里只有单实例插件，回调直接忽略 `_argv`；首次启动也没读 `std::env::args()`。Windows 的「打开方式」是把文件路径作为 argv 传给进程的，应用侧完全没接。
2. **单实例转发丢参数**：应用已运行时，第二个进程的 argv（含待打开文件）被 `tauri-plugin-single-instance` 回调丢弃，只做了「显示并聚焦窗口」。
3. **没有声明文件关联**：`tauri.conf.json` 缺 `bundle.fileAssociations`，安装包不会注册扩展名关联，只能手动「选择其他应用」。

## 修复

### Rust

新增 `src-tauri/src/commands/cli.rs`：

- `files_from_args(&[String]) -> Vec<String>`：从 argv 里挑真实存在的文件。
  - 跳过空串、`-`/`--` 开头的开关（Tauri / WebView2 内部参数）
  - `path.is_file()` 过滤不存在路径，`trim_matches('"')` 处理残留引号
  - 相对路径按 `current_dir()` 转绝对路径（「打开方式」启动时 cwd 常是 System32）
  - 结果去重
- 全局待打开队列 `PENDING` + `push_pending` + 命令 `take_pending_files`（取完即清空，重复调用不重复打开）

`lib.rs`：

- 冷启动：`std::env::args()` 去掉第 0 项（exe 自身）后入队
- 热启动（单实例回调）：`argv.get(1..)` 入队，并 `app.emit("open-files", ())` 通知前端
- 注册命令 `take_pending_files`

### 前端

- 新增 `src/services/launch.ts`：`takePendingFiles()` / `onOpenExternalFiles()`（事件名 `open-files`）
- `src/main.ts` 的 `bootstrap()` 末尾：**先注册监听、再取队列**，逐个 `fileService.openFilePath(path)`
  - 这个顺序保证「取完之后、注册之前」到达的事件不会丢：事件先入 Rust 队列，随后被 `take` 兜住

### 安装包

`tauri.conf.json` 新增 `bundle.fileAssociations`（txt / md / json / yaml / 各类源码扩展名等 40 项），
安装时由 NSIS 注册扩展名关联，`Type` 列显示「以 my-editor 打开文本文件」。

## 生效条件

改的是 exe 与安装包内容，**必须重新 `npm run tauri build` 并重新安装**；只替换前端 dist 不生效。

## 验证

```bash
npm test          # 77 passed
npx tsc --noEmit  # 通过
npm run build     # 通过
cd src-tauri && cargo test --lib   # 153 passed（新增 cli 过滤/队列 2 个单测）
```

手工验证建议：

1. 应用未运行 → 资源管理器右键某 .txt「打开方式 ▸ my-editor」：应启动并打开该文件
2. 应用已运行 → 同样操作：应把窗口拉到前台并新开该文件标签
3. 打开图片（手动选择 exe）：应走图片查看器分支
4. 传不存在的路径（命令行 `my-editor.exe C:\nope.txt`）：应被过滤，不产生空标签
