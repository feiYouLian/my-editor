# 草稿恢复文案精简（2026-10-25）

## 背景

草稿恢复对话框（`src/panels/draftRecovery.ts` + `src/app/sessionHost.ts`）存在三类文案问题：

1. 规则提示冗长：标题已说明草稿数量，提示又重复"勾选要恢复的草稿"。
2. 按钮语义重叠：「全部忽略」与「稍后处理」读起来都像"这次先不管"，前者实为不可撤销删除。
3. 反馈缺失或不一致：恢复失败无任何提示；丢弃消息与对话框标题的数量口径不一致。

## 精简原则

- **标题说数量，提示只说规则**：数量、状态标记放标题与行内，提示只解释用户无法自行推断的后果。
- **按钮说动作，tooltip 只补风险**：按钮文本不重复 tooltip 已含的意思。
- **反馈说结果数量**：操作完成后只报告"成功几个、失败几个"，不重复描述动作。

## 文案对照

### 对话框

| 位置 | 原文案 | 新文案 |
| --- | --- | --- |
| 标题 | 发现 N 个未保存草稿 | 不变 |
| 规则提示 | 勾选要恢复的草稿；原文件已变化的草稿将另存为新的未命名文档。 | 原文件已变化的草稿将另存为副本。（仅存在 stale 草稿时显示） |
| 行内元信息 | 时间 · 大小 · 原文件已变化 | 不变 |
| 丢弃按钮 | 全部忽略 | 全部丢弃 |
| 丢弃按钮 tooltip | 丢弃全部草稿（不可撤销） | 不可撤销 |
| 主按钮 | 恢复选中（N） / 恢复选中（禁用态） | 恢复（N） / 恢复（禁用态） |
| 稍后按钮 | 稍后处理 | 不变 |

未勾选任何草稿时**不新增提示文案**：勾选框是该列表的唯一交互，主按钮禁用态即标准反馈，再加"请先勾选"属于噪音。

### 状态栏反馈

| 场景 | 原文案 | 新文案 |
| --- | --- | --- |
| 全部丢弃 | 已丢弃全部草稿 | 已丢弃 N 个草稿（N = 对话框中可见条目数） |
| 全部恢复 | 已恢复草稿内容（未保存，Ctrl+S 保存） | 已恢复 N 个草稿，Ctrl+S 保存 |
| 部分恢复失败 | 无提示 | 已恢复 N 个草稿，M 个未能恢复，Ctrl+S 保存 |
| 全部恢复失败 | 无提示 | M 个草稿未能恢复 |

说明：未能恢复的草稿不会删除，下次启动仍会出现在列表中。

## 附带行为修正

1. **stale 副本命名**：原实现直接把原文件名（如 `code_test.go`）用作未命名标签名，用户会误以为副本已关联原文件；另存为对话框的默认文件名同为 `code_test.go`，存在覆盖原文件的风险。现改为 `code_test.go（副本）`，与提示"另存为副本"对应。
2. **stale 恢复分支补草稿兜底**：`applyDraft` 后立即 `persistDraft`，与非 stale 分支一致，避免原草稿删除后、内容尚未进入编辑器期间应用异常导致内容丢失。
3. **数量口径统一**：丢弃消息由 `drafts.length` 改为 `rows.length`，与对话框标题展示的条目数一致（读取失败的草稿已在展示前清掉）。
4. 相关注释同步更新（"全部忽略"→"全部丢弃"、"未命名文档"→"副本"）。
