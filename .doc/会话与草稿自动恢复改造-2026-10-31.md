# 会话与草稿自动恢复改造（2026-10-31）

## 目标

对齐 Sublime Text 的会话体验，去掉关闭/启动时的两处打断式弹窗：

1. 关闭标签或退出时不再弹「有未保存的更改」，未保存内容始终自动写成草稿。
2. 启动时不再弹「发现 N 个未保存草稿」让用户勾选，改为自动全量恢复。
3. 关闭时记录标签顺序与「当前选中的标签」，下次启动原样复原。

## 行为变化

| 场景 | 改造前 | 改造后 |
| --- | --- | --- |
| 关闭脏标签 | 三选弹窗（保存 / 不保存 / 取消） | 直接写草稿后关闭（开关可打开弹窗） |
| 退出应用 | 多文件三选弹窗 | 直接写草稿后退出（开关可打开弹窗） |
| 批量关闭脏标签 | 列名确认，提示「草稿恢复」 | 开关关闭时不确认；开启时文案改为「下次启动自动恢复」 |
| 草稿自动保存 | 可被 `draftAutosave` 关闭 | 始终开启，配置项删除 |
| 启动草稿 | 弹列表对话框勾选 | 自动恢复全部草稿，状态栏一条结果消息 |
| 启动标签 | 恢复打开文件与 activeFile | 恢复打开文件、**原始顺序**与**上次选中的标签** |

草稿恢复对「原文件已变化」的条目仍沿用原策略：新建「名字（副本）」未命名标签承载内容，避免覆盖磁盘。

## 配置项

`session.confirmOnClose`（默认 `true`）

- `true`：关闭标签 / 退出前弹三选确认（保存 / 不保存 / 取消），默认行为
- `false`：直接写草稿并关闭，不打断（Sublime 式）

> 2026-10-31 晚调整：最初按「关闭提示」的诉求把默认值设为 `false`，
> 实测后判断"没有提示"更容易让人以为内容丢了，默认改回 `true`。
> 已保存过 `false` 的 config.json 不会自动变，需要在
> 设置 ▸ 文件与会话 ▸ 关闭前提示未保存 里勾一次。

同时删除 `session.draftAutosave`：草稿是未保存内容的唯一兜底，不再提供关闭入口。旧 `config.json` 中的该键会被 Rust 侧反序列化时忽略，下次保存后自然消失。

设置位置：设置中心 ▸ 文件与会话 ▸ 会话与草稿。

## 恢复顺序要点

```text
loadSession()
  → 按 openFiles 顺序：选中项 openFilePath（静默载入），其余 openPending（占位）
  → activate(activeFile / active 标志)
  → autoRestoreDrafts()   // 会激活新标签
  → 重新 activate 会话记录的选中标签
```

「草稿恢复后再激活选中项」这一步是必要的：草稿恢复会新建/激活标签，若不回切，上次选中的标签会被最后一个恢复的草稿顶掉。
