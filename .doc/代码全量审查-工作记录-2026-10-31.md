## 1. 项目定位（从代码反推）

- 产品名：`my-editor`，标题「轻量级定制文本编辑器」，版本 0.5.1（`package.json` / `Cargo.toml` / `tauri.conf.json` 三处一致）。
- 形态：Tauri 2 桌面应用（Windows 为主，macOS/Linux 有分支代码），前端 Vite + TypeScript + CodeMirror 6。
- 目标用户：需要「打开快、能看大文件、编码/换行不乱、能搜能换、能跑小脚本」的开发者与文本工作者。
- 明确的非目标（代码注释中反复声明）：
  - 不做 LSP / 语法树级智能（`search.rs` 的 `find_symbols` 声明为「文本级，不是 LSP」）；
  - 不做插件系统、不做宏录制（`commandPalette.ts` 注释）；
  - 大型文档（≥ 阈值）不进入编辑器，改走只读虚拟视图（`file.rs` / `large.rs`）；
  - 预览/导出不做所见即所得排版（`preview.ts` 固定浅色文档样式）。

### 3.2 状态归属（关键设计）

- **标签**：`store/tabs.ts` 单例 `tabStore`。只有一份 CodeMirror 实例，切标签时换 `EditorState`；每标签缓存最近 8 份状态（>2MB 不缓存，只记光标）。
- **脏标记**：按键路径只置 `contentDirty`（O(1)），800ms 停手后取全文算「长度 + 双 32 位哈希」指纹比对（`tabs.ts` `fingerprint`/`refreshDirty`）。
- **会话**：`session.json`（打开文件 + 光标 + 滚动 + 书签 + 折叠 + 激活项 + 分栏比例）；草稿在 `drafts/<fnv>.json`（全文 + 原文件指纹）。
- **配置**：`config.json`（Rust `AppConfig`，camelCase），前端 `config/settings.ts` 镜像类型；`updateSettings` 整份写回，`subscribeSettings` 触发热更新。
- **工作区**：`workspace.json`（root + expanded），路径在 `load_workspace` / `save_workspace` 时登记进 `PathGuard`。
- **UI 记忆**：侧栏宽度、分栏比例、最近文件、命令面板最近使用 存 `localStorage`（与 config 并存，见问题清单 #12）。

### 3.3 安全模型（代码注释明确声明）

1. Tauri 2 自定义命令**不受 capabilitiy ACL 约束**，故 `PathGuard` 对「破坏/覆盖类」命令做作用域校验：
   - `ensure_root_scope`：新建/重命名/删除/定位，仅限已登记工作区根；
   - `ensure_file_scope`：写二进制/导出补丁/运行/批量转码，允许「根内 / 已登记路径 / 已登记文件同目录 / 已登记目录直接子项」。
2. 读取类命令（打开/列举/探测）保持宽松（必须在对话框里能打开任意文件）。
3. 格式化工具与参数**只从后端 config.json 解析**，前端只传语言键（防 RCE）。
4. 网页抓取：仅 http/https、拒绝 userinfo、默认拦截 loopback/私网/CGNAT/链路本地，开关由 Rust 直接读 config（不信任前端）。
5. 预览与导出统一过 DOMPurify；HTML 预览 iframe `sandbox="allow-same-origin"`（不开启脚本）。
6. 删除走系统回收站；覆盖前有备份（Git 放弃改动快照、批量替换历史）。

| `detect_mojibake` | 乱码诊断（只诊断不改） | 规则一：字节是合法 UTF-8 却按非 UTF-8 解读 → 建议 UTF-8；规则二：异常字符占比/硬标记 → 逐候选做「无损回编码 + 可读性评分」 |

12. 状态栏光标位置（含选中字符数）、总行数、文档统计（行/词/字符，菜单项）。

### 6.4 编码、换行与乱码

1. 三段式编码检测（BOM → UTF-8 合法性（抽样回退到字符边界 + 全量复核）→ chardetng），置信度 `bom/high/low/user`。
2. 候选编码 7 种：UTF-8 / GBK / GB18030 / UTF-16 LE / UTF-16 BE / Big5 / Windows-1252。
3. 状态栏「编码」菜单：重新打开为（不写盘、脏文件先确认）、乱码建议置顶、另存为编码。
4. 乱码自动诊断（打开后）+ 手动「检测乱码并建议编码」：给出原因并可一键重新打开；检测失败与「没乱码」区分。
5. 按文件记忆编码（默认开，仅自动检测置信度低时采用；手动选择会记住）。
6. 换行符切换（LF/CRLF/CR，仅改内存并标脏，需保存生效）；保存时按 `newline` 还原。
7. 保存保留 BOM（UTF-8 BOM 显式写回；UTF-16 由 encoding_rs 处理）。
8. 批量另存为编码（多选文件 + 输出目录 + 目标编码 + 换行策略；非破坏式、同名跳过、只移除成功项）。

### 6.5 预览与导出

4. 双栏滚动联动（双向，rAF 节流 + 块标记插值 + 回显抑制窗口 120ms；图片加载后重新校准）。
5. 预览内查找（纯预览模式的 `Ctrl+F` 接管；MD 容器/HTML iframe 两种作用域与定位）。
6. 图片查看器（自然尺寸回报状态栏、工具条、缩放/适应等见 `preview/imageViewer.ts`）。
7. 导出：HTML（独立文档）、Word（.doc 的 HTML 包装）、PDF（系统打印对话框）、HTML→Markdown（内嵌 `data:image` 落 `.assets` 并改写相对路径）。
8. 导出失败/成功都有明确消息；导出写盘走 `save_file`（原子替换）。

### 6.6 大文件（只读虚拟视图）

1. 分流阈值：≥ `largeFileThreshold`（默认 20MB）或扩展名命中 `largeFile.logExtensions`（默认 `.log`）→ 虚拟视图。
2. 稀疏行索引（默认 64KB 锚点）：首屏 8MB 同步建索引后立即返回，其余后台补齐（进度事件）。
3. 按窗口拉行（视口 ±padding，默认 200 行），单次 ≤4000 行；超长行裁剪到 4000 字符并提示一次。
4. 整文件过滤：大小写/正则开关；流式批次先渲染；命中上限 5 万；可取消。
5. 缩略图密度（前端 240 桶，后端上限 2000）+ 点击/拖拽跳转；主题切换重绘。
6. 编码切换（仅单字节家族，免重建索引）。
7. 自动换行开关（会话级）；横向滚动宽度按已见最长行自适应。
8. 逃生门「以编辑器打开」：≥阈值二次确认；先读成功再释放大文件会话。
9. UTF-16 文件明确拒绝虚拟视图并回退编辑器。

7. 文档统计（行/词/字符）。
8. 格式化：Prettier（js/ts/json/css/md/yaml/html）+ 内置（sql/xml）+ CLI（python/go/rust/java/cpp）；文档级/选区级；超时 5s；工具缺失给安装指引。

### 6.10 界面与个性化

1. 应用主题：深色/浅色/高对比/跟随系统（CSS 变量，`data-theme`）。
2. 编辑器主题：one-dark / light / high-contrast / `custom:<名字>`；自定义主题文件（`themes/*.json`）支持 ui 7 键 + syntax 15 键，颜色结构字符校验，未知键提示，暗色按背景亮度推断。
3. 字号 10–24、字体族（空=等宽栈）、行号、当前行、minimap 开关。
4. 状态栏字段：12 项显隐 + 上下排序（旧配置自动补齐新字段）；图片标签自动隐藏无关字段；只读原因内联显示。

### 6.11 会话、草稿与退出

1. 会话恢复：打开文件顺序、激活标签、光标行列、滚动位置、书签、折叠、分栏比例；`restoreOnStartup` 可关。
2. 草稿：始终开启（不可关）；防抖（默认 1000ms）、未命名标签用 `untitled:<tabId>`；内容回到基线即删除；保存成功即删除（若保存窗口又有输入则重写）。
3. 启动自动恢复草稿：原文件未变就地恢复；已变则另存为「名字（副本）」未命名标签；结果一条消息。
4. 草稿保留天数（0=不清理）、过期清理；替换历史清理。
5. 关闭标签：有未保存且开启确认时三选；关掉确认则直接落草稿关闭。
6. 退出：确认（多文件列出前 5 个）、保存全部失败则不退出、不保存则落草稿；清理有 2.5s 超时兜底，超时仍关窗；关闭前停止运行进程、关闭大文件会话、释放终端。
7. 外部修改：后台标签只标 ⟳ + 通知；切到该标签才弹确认；状态栏「外部修改」三选（重载/比较/忽略）；监听失败提示一次。
8. 文件保存失败：弹可复制详情 + 「另存为/从磁盘重新载入」出路 + 常驻红字 + 通知。

### 6.12 命令、快捷键与菜单体系

1. 单一命令注册表：菜单栏（文件/编辑/选择/转到/视图/比较/工具/设置）、命令面板、快捷键、设置键位页全部由 `commandTable.ts` 派生。
2. 键位解析：`Mod/Alt/Shift/主键` 记法，基于 `e.code`（IME/布局稳定）；用户覆盖存 `keybindings`；`fixed` 命令只展示不可改；`altKeys` 固定别名（如 `Mod-Shift-L` 格式化）。
3. 保留键：Mod-Z/Y/A/C/V/X//、Mod-G、Mod-Alt-G、Alt-↑/↓、F2/F3 系列、Ctrl-F2 + 动态列编辑器键；这些全局分发器不抢。
4. 分发：window 捕获阶段；表单元素内不派发；模态（dialog/settings/diff/palette）内只阻止浏览器默认键；WebView2 默认键（Ctrl+S/P/O/N/F/G/R）被主动阻止。
5. 冲突检测：录制新键时检查保留键与占用命令，冲突时二次确认。
6. 快捷键速查对话框：按 section 分组，只列已绑定项。
7. 菜单与弹出菜单支持键盘导航（↑↓/Home/End/Enter/Space），关闭后归还焦点；模态关闭后自动恢复之前的焦点。

### 6.13 其它工程性能力

1. 启动耗时采样（`startup.json`）。
2. 全局 unhandledrejection 兜底：白名单（AbortError/用户取消）不弹窗，其余弹可复制详情。
3. 无边框窗口：拖动区域、8 个缩放热区、最大化图标同步（不设 title 避免 tooltip 干扰）。
4. 子进程一律 `CREATE_NO_WINDOW`（避免黑框闪烁）；重活统一 `spawn_blocking`。
5. 读取/写入/遍历/索引/过滤等大操作均有体积上限与截断提示。

## 7. 已确认问题清单（含证据、后果、建议）

> 分级：P1 = 功能不可用 / 数据风险；P2 = 边界缺陷或一致性冲突；P3 = 规范 / 性能 / 体验建议。
> 每条都经过源码交叉验证（必要时看了依赖库实现），标注「确认」或「高概率」。

### P1-1【确认】大文件视图「切换编码」参数名不匹配，必然失败

- 前端：`largeView.ts:524` → `invoke("set_large_encoding", { id: info.id, encoding: next })`
- 后端：`large.rs:736` → `pub fn set_large_encoding(state, id: String, encoding_name: String)`
- Tauri 按参数名反序列化（snake_case ↔ camelCase），`encoding` 无法匹配 `encodingName`，调用直接报 invalid args。
- 后果：大文件/日志视图右上角编码下拉切一次弹一条「切换编码失败：invalid args…」，功能实际不可用。
- 建议：前端改为 `encodingName: next`（或后端参数改名 `encoding`），并在 `LargeView.changeEncoding` 失败时回滚下拉值（当前下拉会停留在新值，界面与实际不一致）。

### P1-2【确认】非 UTF-8 文件的工作区搜索 / F12 符号定位失效

- `search.rs:400`：`let text = String::from_utf8_lossy(&bytes);`（搜索）
- `search.rs:976`：同样 lossy（符号定位）
- 对照：`replace_one`（`search.rs:678-680`）却做了编码检测 + 严格解码；`file.rs` 打开文件也做三段式检测。
- 后果：GBK/GB18030/Big5 文件里的中文关键词搜不到（字节被替换为 U+FFFD），F12 找不到符号；ASCII 关键词能命中但周围内容乱码；替换链路按真实编码检测，与搜索行为不一致；与「编码不乱」的产品定位直接冲突。
- 建议：搜索/符号定位复用 `encoding::guess + decode`（可用「BOM → UTF-8 全量校验 → chardetng」并缓存每文件编码）；或至少在结果里标注「N 个非 UTF-8 文件未解析」。

### P1-3【确认】状态栏「缩进」弹出菜单点击后立即关闭

- `main.ts:191`：`statusIndent.addEventListener("click", (e) => { … openStatusMenu<string>({ … }) })` —— 没有 `e.stopPropagation()`。
- `statusMenu.ts:113-121`：`openStatusMenu` 在点击回调内 `document.body.append(menu)` 后立刻 `document.addEventListener("click", onDocClick)`。
- DOM 事件仍在冒泡：同一次点击到达 document 时，新加的监听器被调用 → `closeStatusMenu()` → 菜单一闪而过。
- 对照：`statusActions.bind`（`statusActions.ts:66-82`）对换行/语言/编码都调了 `e.stopPropagation()`，所以那三个菜单正常。
- 后果：状态栏「缩进: 2」无法通过点击修改（只剩设置页的全局缩进）。
- 建议：该 handler 加 `e.stopPropagation()`；或把 `onDocClick` 注册延后到 `setTimeout(…, 0)` / 用 capture-phase 且判断事件时间戳，统一在 `openStatusMenu` 内兜底。

### P1-4【确认】状态栏「外部修改」三选菜单同样点击即关

- `sessionHost.ts:147`：`this.externalBadgeEl.addEventListener("click", (e) => { … openStatusMenu<null>({ … }) })` —— 同样没有 `stopPropagation()`。
- 后果：「重新载入磁盘内容 / 与磁盘内容比较 / 忽略本次修改」这个入口不可用；用户只能改用标签右键「重新载入（从磁盘）」或通知中心「处理」。
- 建议：同上；可把「阻止冒泡」收进 `openStatusMenu`（记录 `event.timeStamp`，同一事件不关闭）。

### P2-1【确认】未打开工作区时「插入剪贴板图片」必然被安全策略拒绝

- 前端写入：`fileService.ts:312-322` → 目标 `${dir}/${base}.assets/image-*.png`，直接 `invoke("write_binary_file")`，**没有先把 `.assets` 目录登记**。
- 后端校验：`paths.rs:156-177` `ensure_file_scope` 只放行「已登记根内 / 已登记路径 / 已登记文件的同目录 / 已登记目录的直接子项」。
  - `tab.path` 的父目录是 `${dir}`，而目标父目录是 `${dir}/${base}.assets`，两者不等 → 拒绝。
- 后果：只打开单个文件（没有打开目录作为工作区）时，右键「插入 ▸ 剪贴板图片」必报「路径不在已打开的工作区/文件范围内」。工作区内正常。
- 对照：导出 Markdown 的素材目录（`previewHost.ts:255-259`）先 `register_paths([folder])` 再写，所以那条链路没问题。
- 建议：`insertClipboardImage` 写前 `await invoke("register_paths", { paths: [assetsDir] })`；或后端允许「已登记文件同目录的下一层子目录」。

### P2-2【确认】工作区外文件「在文件管理器中显示」被拒，并以「操作失败」弹窗呈现

- 前端：`main.ts:715-717`（正在打开的文件右键）、`openEditorsView.ts:126-129` → `void invoke("reveal_in_file_manager", { path })`（没有 catch）。
- 后端：`fs.rs:316-322` → `ensure_root_scope(&path)`，工作区外路径不在任何 root 内 → Err。
- 后果：打开单个文件后点该菜单，抛出未捕获 Promise 拒绝 → 全局 `unhandledrejection` 弹「操作失败」+ 安全策略文案；用户不理解为什么「看一眼文件在哪」也不行。
- 建议：`reveal_in_file_manager` 改为只做 `add_path` 宽松校验（只读操作，不写盘），或前端捕获并给出可执行提示。

### P2-3【确认】快速打开 / 分支面板超过 200 条时键盘选中态丢失

- 渲染只输出前 200 条：`quickOpen.ts:242`（`visible.slice(0, MAX_RENDERED)`）、`branchPicker.ts:193`。
- 选中态更新：`quickOpen.ts:280-286`、`branchPicker.ts:229-235` 用 `listEl.children[this.selected]`，而 `selected` 的取值范围是 `visible.length`（可达 5000 / 全部分支）。
- 后果：按 ↓ 越过第 200 条后，没有任何行被高亮；`children[200]` 恰好是「仅显示前 200 条」提示或 undefined；Enter 仍能打开正确文件（`visible[selected]`），但用户看不见选中谁。
- 建议：`move()` 把 `selected` 夹紧到 `Math.min(visible.length, MAX_RENDERED) - 1`，或按窗口滚动渲染。

### P2-4【确认】分栏比例存在三个真源，互相覆盖

- `localStorage['my-editor.splitRatio']`：拖动分割线写入（`layout.ts:158-170`）、`statusBar.setSplitRatio` 写入（`statusBar.ts:338-347`，设置页滑杆也走这里）。
- `config.layout.splitRatio`：设置页 `change` 时写回（`layoutTab.ts:56-61`）。
- `session.json.splitRatio`：会话保存（`sessionHost.ts:181-188`）与启动恢复（`main.ts:1710`）。
- 启动顺序：`layout.applyConfiguredSplitRatio()`（`layout.ts:193-202`）在 localStorage 有值时直接 return → config 值被忽略；随后会话恢复 `setSplitRatio(session.splitRatio)` 又把 localStorage 覆盖。
- 后果：改 `config.json` 里的 `splitRatio` 基本不生效（除非清 localStorage）；设置页滑杆与拖动结果以 localStorage 为准，容易让用户觉得「设置没保存」。
- 建议：收敛为单一来源（建议 config 为唯一持久化，session 只存临时态），或在文档/UI 明确「比例以本次拖拽为准」。

### P2-5【确认】通知中心 `dedupeKey` 未生效

- `noticeStore.ts:41-56`：`if (dedupeKey) { const existing = notices.findIndex((n) => n.kind === kind && n.text === text); … }` —— 按 kind+text 匹配，完全没用 `dedupeKey`。
- 后果：同一标签多次外部修改（text 里带标签名，若名字不变则去重；但同一文件被改两次时 text 相同 → 会去重，反而是「不去重也不对」）；不同文件的 Git 失败（text 含具体错误，可能变化）会堆多条；`saveFail` 与 `draft:${tabId}` 等调用方以为按 key 去重。
- 建议：给 Notice 增加 `key` 字段并按 key 去重（保留最新），`text` 只用于展示。

### P2-6【确认】差异面板「先建全部 DOM 再分帧 append」，大 diff 仍会卡；导航可能定位不到

- `diffPanel/render.ts:104-130`：先把每一行 `buildDiffRow` 成元素塞进 `items`（同步构建，行数可达数万），再每帧 append 600 个。
- `diffPanel.ts:259-267` `scrollToHunk` 用 `querySelector('[data-hunk="N"]')`，未渲染批次里的 hunk 找不到 → 不滚动、也不重试。
- 后果：几万行差异打开时主线程仍会长时间占用（注释声称的分帧保护没有覆盖建 DOM 本身）；在渲染完成前点「下一处」可能无反应。
- 建议：把 `push(i)` 也放进分帧循环；`scrollToHunk` 记录 pendingHunk，渲染批次完成后再尝试。

### P2-7【确认】前后端默认配置不一致

1. 状态栏字段：Rust 默认 11 项（`config.rs:105-125`，无 `indent`），前端默认 12 项（`settings.ts:214-229`，含 `indent`）。
   - 影响：首次由 Rust 生成 config.json → 设置页 `withAllFields` 把 `indent` 追加到末尾；用户保存后顺序被固化。`statusBar.applyFields` 对缺失项默认可见，因此功能不坏。
2. formatters：Rust 默认含 `rust`（`config.rs:423-461`），前端 `defaultConfig` 缺 `rust`（`settings.ts:311-316`）。
   - 影响：仅当 `load_config` 失败回退前端默认时，`getConfig().formatters.rust` 缺失；`formatText` 会用 `cliFormatters` 兜底，因此仍可格式化。
- 建议：两侧默认值抽成同一份「契约清单」并加一致性测试（Rust 单测已有部分往返测试，但无法跨语言比较）。

### P2-9【确认】日志扩展名匹配口径前后端不一致

- 前端：`largeFileHost.ts:58-61` → `getConfig().largeFile.logExtensions.includes(extension)`（区分大小写、要求配置带点）。
- 后端：`file.rs:129-139` → 扩展名小写加 `.` 前缀，配置也归一化后比较（不区分大小写、带不带点都行）。

### P2-10【确认】「文档统计」对大文件虚拟视图给出 0 行 0 词

- `commandTable.ts:284-294` 只判断 `tab.kind === "text"`，虚拟标签也是 text；`tabStore.snapshotOf` 对虚拟标签返回空串（content 为空）。
- 后果：状态栏明明显示「共 N 行」，菜单统计却显示 0 行，互相矛盾。
- 建议：虚拟标签改用 `tab.totalLines`，或直接提示「只读视图不支持统计」。

### P2-11【确认】列编辑器键重绑后「保留键」不刷新

- `setExtraReservedKeys` 只在模块加载（`main.ts:1542`）与 bootstrap（`main.ts:1683`）调用；`subscribeSettings` 回调（`main.ts:920-928`）没有重新调用。
- 设置页重绑 `columnEditorKey` 后（`keybindingsTab.ts:225-230`），`buildKeymap` 会经 Compartment 重配（新键生效），但：
  - 旧键仍在 `extraReserved` 里 → 原本可以绑定给全局命令的键被永久占住（直到重启）；
  - 新键不在保留集 → 若与某全局命令冲突，全局命令优先（录制时虽会提示冲突，但用户若在 config.json 手改则无提示）。
- 建议：`subscribeSettings` 里同步 `setExtraReservedKeys([settings.columnEditorKey])`。

### P2-12【确认】`Ctrl+Shift+L` 被「格式化文档」占用，CM6「选中全部匹配」失效

- `@codemirror/search` 的 `searchKeymap` 含 `Mod-Shift-l` → `selectSelectionMatches`（已核对 `node_modules/@codemirror/search/dist/index.js`）。
- `commandTable.ts:172`：`edit.format` 的 `altKeys: ["Mod-Shift-L"]`；全局分发是 window 捕获阶段并 `stopPropagation`（`main.ts:1623-1643`），CM6 收不到。
- 代码注释（`keybindings.ts:80-81`）说明这是「特意借用」，但属于**静默覆盖内置能力**：用户按 Ctrl+Shift+L 期待选中全部匹配，实际格式化了整篇文档。
- 建议：换成不冲突的别名（如 `Ctrl+Alt+Shift+F`），或在快捷键速查里明示这一占用。

### P3-1【确认】代码规范/一致性问题

1. `ui/dialogs.ts` 中 5 处 `trapFocus(dialog);` 顶格缩进（83/139/227/289/357 行），与文件其它代码缩进不一致（不影响功能）。
2. `settingsHelp.ts` 的 `workspace` 生效方式标注与实际不符（见 P2-8）。
3. `edit.foldAll` / `edit.unfoldAll` / `edit.complete` 的 `title` 里写死了快捷键文本（`commandTable.ts:178-180`），与「标题不写键位」的其它条目不一致；键位改了标题不会变。
4. `session/git/…` 多处手写 `String(e).split("\n")[0]` 提取首行错误，重复 50+ 次（本次统计 57 处），可抽公共函数（纯可维护性）。

### P3-2【确认】性能/资源注意点

1. `editor/setup.loadDocument` 的缓存快速路径会用 `cached.state.doc.toString() === content` 做全文比较（同标签再次载入时 O(n)）；大文件下每次切回都有一次全文构造，可改为「长度 + 指纹」或直接信任 docId + 内容未变标记。
2. `terminal.rs:372-390` 每读 8KB 就发一个 base64 事件；`dir /s` 之类高速输出会产生事件风暴（前端逐条 write）。可做 16–64KB 批量或按帧合并。
3. `large.rs` 的 `open_large_file` 在命令线程同步扫 8MB 建索引；`session.rs` 的 `list_drafts` 同步遍历所有草稿并 fingerprint 原文件（可能读多个 4MB 文件）→ 启动/打开大文件时存在主线程阻塞风险（命令非 async）。
4. `minimap.ts` 在 5 万行以内全量扫描、2 万行以内逐行分类（文档变更后 150ms 重建），大文档编辑时仍有可感知开销（已有降级策略，属可接受）。
5. `preview/localImages.ts` 的 `probe_file` 会把「预览里出现过的图片路径」登记进 PathGuard（读取类命令宽松，无安全问题，但会让作用域集合随预览增长）。

### P3-3【确认】其它边界与体验点

1. `quickOpen.ensureFiles` 的 `loading` 是单标志：切换工作区时若上一次请求仍在飞，新 root 直接 return，列表会短暂显示旧工作区文件（`quickOpen.ts:169-173`）。
2. 路径比较未统一规范化：`fileTree.canReveal`（`fileTree.ts:537-539`）用 `startsWith(root)`，`tabStore.findByPath`（`tabs.ts:729-731`）用严格相等；Windows 下大小写/分隔符不同（例如经 Git 视图打开 `D:/repo/a.ts` 与文件树 `D:\repo\a.ts`）会导致「切标签不定位」「脏文件判断漏判」。建议统一 `normalizePath`（`replace(/\\/g,'/').toLowerCase()`）。
3. `newUuid` 在 `globalThis.crypto` 完全缺失时会对 undefined 调用 `getRandomValues`（`stamps.ts:29-33`）；Tauri WebView 不会触发，但作为纯函数应有兜底。
4. `tabStore.openVirtual` 替换同路径普通标签时未先 `syncContent(activeId)`（`tabs.ts:246-269`）；若被替换的是当前激活且有未同步输入，会丢内容（极端路径，属防御性缺陷）。
5. `saveSettings` 失败时设置页控件视觉已切换、内存配置未变（`settings/shared.ts:54-61`），直到重绘才回正；失败提示依赖 `settingsNotify`（面板关闭后为空）。
6. `fetch.allowPrivateNetwork` 没有设置 UI（`fetchPageDialog.ts:112-115` 只提示改 config.json），对普通用户等于不可发现。
7. `fileTree` 目录改名后若该目录下有已打开标签，`onPathMoved` 会同步；但 `recentlyClosed` 里记录的旧路径不会同步（重开该标签会失败并提示）。
8. `media` 类导出：PDF 走系统打印，`openPrintDialog` 60s 后移除 iframe；若用户打印对话框停留超过 60s，打印任务可能被中断（低概率）。

### P2-13【确认】大文件视图的编码下拉缺少 Windows-1252，且选值会被错误显示为 UTF-8

- 后端候选：`encoding.rs:7-9` 共 7 个（含 `Windows-1252`）。
- 前端下拉：`largeView/constants.ts:18` 只有 6 个（无 `Windows-1252`）。
- 打开时：`largeView.ts:140` → `encodingSelect.value = ENCODINGS.includes(info.encoding) ? info.encoding : "UTF-8"`。
- 后果：若大文件被检测为 Windows-1252，下拉显示「UTF-8」而内容实际按 1252 解码（状态栏显示 1252）——界面自相矛盾；用户也无法在视图内选回 1252。
- 建议：`ENCODINGS` 与后端 `CANDIDATES` 单一来源（可用一次 IPC 拉取），检测值不在列表时补一个临时 option。

### P2-14【确认】状态栏「换行符」对只读 / 虚拟标签可切换，产生脏标记

- `statusActions.ts:87-92`：`showNewlineMenu` 只检查 `tab.kind !== "text" || !tab.path`，虚拟标签（kind=text、有 path、readonly）也能进入。
- `tabStore.setNewline`（`tabs.ts:682-691`）会 `refreshDirty`：`newline !== savedNewline` → `dirty = true`。
- 后果：大文件虚拟视图或 `.log` 只读标签点一下换行符 → 标签出现「● 未保存」；保存被 `blockIfReadonly` 拦住，只能改回原值或重开（提示还引导 Ctrl+S）。
- 建议：`showNewlineMenu` 与语言菜单一致，拒绝 `tab.virtual` 与 `tab.readonly`；或 `setNewline` 对只读返回 false。

### P2-15【确认】状态栏「编码」菜单在大文件虚拟视图上无效且会误导

- `statusActions.ts:158-197`：`showEncodingMenu` 同样只检查 kind/path，虚拟标签可进入。
- `reopenWithEncoding` → `readDiskAs` → `tabStore.reopenWith`（`tabs.ts:694-713`）会改写 tab 的 encoding/newline/content；但虚拟标签的内容来自后端 large 会话，`largeId` 与视图的 `info.encoding` 不变。
- 后果：状态栏编码变了、提示「已重新打开为 X」，但屏幕内容仍按旧编码解码；且可能把虚拟标签标脏。
- 建议：`showEncodingMenu` 拒绝 `tab.virtual`（与 `showLanguageMenu` 一致），虚拟视图的编码切换走视图内下拉（修好 P1-1 后）。

### P2-16【确认】Markdown 本地图片内联在非 Windows 平台失效

- `preview/localImages.ts:63/67/69/75/81`：路径统一把 `/` 换成 `\`，再用反斜杠拼 `${baseDir}` 与相对路径。
- 后果：macOS / Linux 上 `\` 不是分隔符，`probe_file`/`read_image_file` 找不到文件 → 预览与导出都丢本地图片（Windows 正常）。
- 建议：用平台分隔符或直接使用 `/`（Rust 侧在 Windows 接受 `/`），必要时用 `core/paths.ts` 统一处理。

### P2-17【确认】导出 Markdown 的素材目录用反斜杠拼接，非 Windows 会写成怪文件名

- `previewHost.ts:281`：用 `${folder}` + 反斜杠 + `${fileName}` 拼接写入路径。
- 后果：Linux/macOS 上会创建名为 `<title>.assets\image-1.png` 的单文件，而不是目录内文件；随后 Markdown 里的相对路径 `assets/image-1.png` 找不到图。
- 建议：同 P2-16，统一用 `/` 或 `path.join` 等价逻辑。

### P3-4【确认】其它交互/可用性小问题

1. 虚拟视图下 `Ctrl+F`（`commandTable.ts:248-254`）会打开编辑器查找面板，但编辑器被 `virtual` 类隐藏 → 用户看不到面板；建议虚拟视图下提示「请用视图内过滤」。
2. `panel/menubar.ts` 无键盘导航（只有点击与悬停切换），与 `placeMenu` 的 ↑↓/Enter 支持不一致。
3. 状态栏消息默认 3s，`git` 失败 8s；但 `showMessage` 叠加时只显示「（+N）」，历史消息需点开通知中心——可发现性依赖用户点状态栏。
4. `recentFiles` 只存 localStorage，不校验文件是否仍存在；点击已删除文件会走“打开失败”路线（有提示，无清理）。
5. `aboutDialog` 版本回退默认 `"0.1.0"`（`aboutDialog.ts:21`），与真实版本 0.5.1 不一致；仅在 `getVersion()` 失败时出现。
6. `sessionHost.forgetDraft` 不清 `restoredCursors/sessionCursors`（`sessionHost.ts:425-433`），长时间会话会缓留少量已关闭路径（数量级小）。
7. `fileTree` 的 Git 目录染色只对「已渲染节点」生效（`refreshGitMarks`），折叠目录展开后由 `createNode` 重新取状态，无问题；但目录状态在文件被删除后不会主动移除（依赖下一次 Git 刷新）。

### P3-5【确认】重做键位显示与 Windows 实际绑定不一致

- `commandTable.ts:309`：`edit.redo` 的 `defaultKey` = `Mod-Shift-Z`（fixed）→ 菜单/快捷键速查显示 `Ctrl+Shift+Z`；`app/menuContent.ts:93` 右键菜单硬编码 `Ctrl+Shift+Z`。
- 实际绑定（`node_modules/@codemirror/commands` 的 `historyKeymap`）：`{ key: "Mod-y", mac: "Mod-Shift-z", run: redo }` + `{ linux: "Ctrl-Shift-z", run: redo }`；**Windows 只有 `Ctrl+Y`**。
- 后果：Windows 上按 `Ctrl+Shift+Z` 无任何反应（该键又在保留集里，全局分发不会接管），文档/速查与行为不一致。
- 建议：在 `editor/keymap.ts` 补 `{ key: "Mod-Shift-z", run: redo }`（并保留 `Mod-y`），或让展示按平台解析。

### P3-6【确认】Git 行「双击打开文件」会先触发 diff

- `panels/gitView.ts:419-427`：`bindOpenGesture(row, { forceSingleClick: true, onOpen: diff })`，同时另绑 `dblclick → openFile`。
- 双击时浏览器会先派发两次 click（→ diff 两次），再派发 dblclick（→ 打开文件），与注释「单击看 diff、双击打开文件」不符。
- 建议：在 dblclick 中结合 `e.detail` 抑制单击动作，或去掉双击打开。

### P3-7【确认】大文件视图可切到 UTF-16，但字节级行扫描不支持

- `largeView/constants.ts:18` 的下拉含 `UTF-16 LE`/`UTF-16 BE`；`large.rs:736-748` 的 `set_large_encoding` 只校验 `lookup` 能解析，未限制单字节家族。
- 虚拟视图按字节找 `\n`、再逐行按该编码解码；UTF-16 的换行是双字节，切过去会行错位/乱码（只读视图，可切回）。
- 建议：下拉过滤 UTF-16（或后端拒绝非单字节编码）；文档/UI 不要暗示支持。

10. **原子写**：临时文件 → `sync_all` → rename（失败重试 1 次）→ 失败清理临时文件（`file.rs:270-298`）。
11. **自身写盘事件抑制**：`mark_writing`/`note_written` 包裹保存与批量替换，且失败也调用 `note_written`（`file.rs:348-361`、`search.rs:584-586`），不会把自身写入误报为外部修改。
12. **大文件锚点不变式**：锚点只落在换行符之后（行首），并有单测 `anchors_always_land_on_line_start`。
13. **单实例**：第二个实例拉前窗口并转发 argv 文件，避免并发写 session/drafts（`lib.rs:20-34`）。
14. **子进程黑框**：所有 `Command` 统一走 `no_console`（git/格式化/运行/taskkill/explorer 之外的 cmd 调用），Windows GUI 进程不会闪黑框。
15. **退出兜底**：清理 2.5s 超时后仍 destroy 窗口（`windowChrome.ts:174-189`），且 `capabilities` 已放行 `allow-destroy`。
