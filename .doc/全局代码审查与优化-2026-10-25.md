## 一、结论摘要

整体工程质量偏高：关键安全点（Markdown `html:false` + DOMPurify、HTML 预览 iframe 沙箱、
打印 iframe 沙箱、PathGuard 词法规范化 + canonicalize、格式化工具白名单、进程代际令牌、
标签切换代际令牌、惰性快照）都做在了正确的位置，且注释解释了「为什么」。

问题集中在三处「关键不变式没有贯彻到底」：

1. **脏标记基线的取值时机**：保存返回后把「编辑器最新内容」当作基线，保存窗口内的输入被静默记为已保存；
2. **单编辑器实例的文档代际**：`loadDocument` 的异步窗口缺少令牌校验，快速切标签可能跨文档污染；
3. **「同步命令 = 主线程」这条项目规则**：多个同步命令仍在主线程做 fsync / 递归删除 / base64 / taskkill。

另有若干热路径浪费（每按键重建快捷键表、每滚动帧逐元素测量布局）、路径守卫越权面、
自身写盘静默窗口吞掉外部修改、生产 CSP 仍放行 localhost。

人工冒烟建议（改动集中在状态机与保存链路，建议逐项过一遍）：

1. 打开大文件编辑 → `Ctrl+S` → 保存瞬间继续输入 → 关闭标签应弹「未保存」确认；
2. 快速连点两个不同语言的标签（含首次打开的 `.md`）→ 高亮与状态栏语言应始终跟随当前标签；
3. 双栏 Markdown 预览：格式化文档、滚动联动、图片加载后校准；
4. 切换空白字符与自动换行（300ms 内连续操作）→ 重开应用两项都保持；
5. 文件树删除大目录、打开终端、运行 Python/cURL、抓取网页 → 窗口不应出现「未响应」；
6. 保存后 1.5s 内用外部工具改写同一文件 → 状态栏应出现「外部修改」；
7. 连续切换状态栏换行符/编码/语言菜单，确认目标标签不串台。
