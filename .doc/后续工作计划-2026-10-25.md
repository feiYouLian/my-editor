## 4. P1-1 批量替换的验收边界（先定清楚再动手）

| 约束 | 要求 |
|---|---|
| 预览 | 替换前展示"文件 → 命中行 → 替换后文本"，可取消 |
| 确认 | 默认按文件二次确认；提供"全部应用"但需显式勾选 |
| 备份 | `globalReplace.backup=true` 时写 `<file>.bak`，失败可从备份恢复 |
| 编码/换行 | 保持原文件编码与换行符（复用 `encoding_rs` 与 `save_file` 的语义） |
| 幂等 | 同一文件被外部修改后（指纹变化）跳过并报告，不覆盖 |
| 上限 | 单次最多 N 个文件（默认 200），超出拒绝并提示缩小范围 |
| 失败处理 | 任一文件失败：已成功的不回滚（有 .bak），报告清单可追溯 |

## 5. 明确不做（维持现状）

| 不做 | 理由 |
|---|---|
| LSP / 智能补全 / 插件系统 | 与"轻量文本工具"定位冲突，成本远超收益 |
| AI 功能落地 | 当前无消费场景；先把 `ai` 配置删掉，避免"看起来有" |
| 主题市场 / CSS 注入 | 维护成本高；"跟随系统"已够用 |
| 搜索流式推送 / 索引落盘 | 上限内一次性返回已够，先不做状态机与磁盘索引 |
| 文件树内拖拽移动文件 | 与"拖放打开"不是同一交互，需要冲突/撤销设计，价值低于批量替换 |

## 6. 每批次的固定动作

```text
npx tsc --noEmit
npm run build
cd src-tauri && cargo test --lib
```

外加：
1. 改动涉及配置字段时，Rust `config.rs` 与前端 `settings.ts` 双端同步（含 `Default`）。
2. 新交互（拖拽/拖放/面板）必须在回复中给出 3 条以内手工冒烟步骤。
3. 文档：功能变化写入 `.doc/` 既有文档的"实施记录"，不新建散落文件。
