# 重新加载（Reload）功能（2026-10-31）

编辑器里「reload」有两种粒度，本次把两级入口都补齐（命令表驱动，菜单 / 命令面板 / 快捷键 / 键位设置自动同步）。

| 命令 id | 作用 | 默认快捷键 | 入口 |
| --- | --- | --- | --- |
| `file.reload` | 重新载入当前文件（丢弃编辑器内未保存修改，脏标签会先确认） | `Ctrl+R` | 文件 ▸ 重新载入当前文件 |
| `view.reloadWindow` | 重新加载界面（前端整体重载，会话与草稿先落盘） | `Ctrl+Shift+R` | 视图 ▸ 重新加载界面 |

## 实现要点

- `src/app/commandTable.ts`
  - `file.reload` 补上此前缺失的 `defaultKey: "Mod-R"`
  - 新增 `view.reloadWindow`（`section: "视图"`），执行体由 ctx 注入
- `src/main.ts`
  - 注入 `reloadWindow: async () => { await sessionHost.flush(); window.location.reload(); }`
  - `BROWSER_DEFAULT_KEYS` 增加 `KeyR`：WebView2 的 Ctrl+R 默认会直接刷新页面，
    绕过落盘会造成最近 1s 内的输入丢失；现在 Ctrl+R 只走命令（未绑定或被改键时也只是被拦住）
- `src/app/sessionHost.ts` `flush()`
  - 会话写盘改为 `await saveSession(...)`。原来走 `saveNow()`（fire-and-forget），
    重载界面会中断未完成的 IPC，可能还没写盘页面就换了

## 为什么需要 flush

重载界面等价于「关掉前端再重新启动」：`bootstrap()` 会走会话恢复 + 草稿自动恢复。
若重载前不落盘，防抖窗口（默认 1000ms）内的输入既没进草稿也没进会话，重载后就丢了。

手工验证：

1. 打开一个文件，改两行（不保存），按 `Ctrl+Shift+R`：界面重载后标签与未保存内容都还在
2. 在文件被外部程序修改后按 `Ctrl+R`：应弹「重新载入」确认，而不是刷新页面
3. 设置中心 ▸ 快捷键：两条命令都在可改键列表里
