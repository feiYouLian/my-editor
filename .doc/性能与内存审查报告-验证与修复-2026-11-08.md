# 性能与内存审查报告：验证与修复记录

- 验证对象：《my-editor 性能与内存占用审查报告》（2026-11-08，口径为 v0.8.0 静态审查 + 纯逻辑微基准）
- 验证日期：2026-11-08
- 约束：**不影响现有功能**（行为可观察变化一律不改，只修确定性的资源泄漏与纯分配开销）
- 结论：报告的核心事实链成立，2 个 P0 与 1 个 P2 已修；报告里 3 条建议按原样实施会改变现有行为，已改为等价但不改行为的做法或在本文说明不采纳理由。

## 1. 逐条核对

| 报告项 | 核对结果 | 证据 |
|---|---|---|
| P0-1 重载不释放后端资源 | **成立** | `main.ts` 的 `reloadWindow` 只 `flush()` 后 `location.reload()`；Rust 侧 5 个 `manage` 状态在 `lib.rs:43-47`，Webview 重载不重新执行 setup；`terminal.rs:202-204` 的上限按后端会话表计算 |
| P0-2 关闭大文件会话后索引线程跑完整个文件 | **成立** | `large.rs` 索引线程循环无取消检查，会话校验只在线程末尾；`close_large_file` 原实现只有 `map.remove` |
| P0-2 附带的「`LargeView.close()` 不调 `cancel()`」 | **成立但不应按报告修** | `close()` 只在**切换标签**时调用（`tabSwitcher.ts:69,95`），关标签走 `largeFileHost.release()`，其中已 `await this.instance?.cancel()`。若在 `close()` 里补 `cancel()`，「切走标签」会中止正在进行的过滤，切回来结果就没了——属于行为改变 |

| P1-1 微基准量级 | **成立** | 本机复刻 `fingerprint`（Node 20，5 次取最小）：1MB 1.9ms / 5MB 13.8ms / 20MB 55.1ms，与报告 2.5 / 9.5 / 39.6ms 同量级 |
| P1-2 全文变换落整篇撤销栈 | **成立** | `setup.ts` 的 `applyDocTransform` 用 `from:0 → to:before.length` 整篇替换，默认进 history |
| P1-3 草稿/保存瞬时副本 | **成立** | `sessionHost.persistDraft` → `snapshotOf` → `writeDraft` 整篇跨 IPC；`file.rs` 再 `apply_eol` + `encode` |
| P2-1 4MB 块扫描 `collect()` 临时 Vec | **成立** | `large.rs` 的 `Indexer::step` 原为 `memchr_iter(...).collect::<Vec<usize>>()` 后再遍历 |
| P2-2 `restoredCursors` / `sessionCursors` 无界增长 | **不成立** | `restoredCursors` 在 `applyRestoredCursor` 里消费即 `delete`；`sessionCursors` 只在启动 `primeRestoredCursors` 填一次，key 是 path（重复打开会覆盖），不会随运行时长增长 |
| P2-2 单例观察器未 `disconnect` | **成立但当前无害** | 均为应用级单例，页面重载随 JS 上下文回收；`largeView` 的 4 个全局 `listen` 已补成对释放 |
| P2-2 `SessionHost` 15s `setInterval` 无 handle | **成立但当前无害** | 单窗口常驻，退出/重载即随上下文销毁，未新增 `dispose()` |

## 2. 已修内容

### 2.1 P0-1：重载前释放后端资源

`src/main.ts`：抽出 `releaseBackendResources()`，退出（`onBeforeExit`）与「重新加载界面」（`reloadWindow`）共用，顺序为
`stop_run` → `cancel_large_task` → 逐个 `close_large_file` → `largeHost.dispose()` → `terminalHost.dispose()` → `terminal_close({ id: "" })` 兜底。

- 兜底全清的意义：前端 `sessions` 漏记（事件丢失 / 更早一次重载的遗留）时，空 id 让后端 `drain()` 所有 PTY，槽位不会被占满。
- 重载后大文件标签仍能恢复：会话恢复对激活标签走 `fileService.openFilePath`（重新 probe + `open_large_file`），非激活标签走占位标签，首次激活时 `loadPendingTab` 重新探测。因此重载前关闭会话不影响标签恢复。

### 2.2 P0-2：大文件会话取消标志

`src-tauri/src/commands/large.rs`：

- `LargeFile` 新增 `cancel: Arc<AtomicBool>`，`open_large_file` 时创建并随会话存入 map。
- 后台索引循环抽成 `drain_index(idx, cancelled, on_step)`：**每块开头检查一次**，取消即返回 `false`，线程直接退出（不再写回结果、不再发进度事件）。
- `close_large_file` 先置位再 `map.remove`，正在读的那一块（≤4MB）读完后即停。
- `refresh_large_file` 的续扫循环同样检查该标志，关闭后不再续读 32MB。
- `cancel_large_task` **保持原语义**（只取消过滤），不动索引；原因见第 1 节。

新增单测：`drain_index_stops_after_cancel`（第一块后置位，断言 `pos == CHUNK`、返回 `false`）、`drain_index_scans_to_eof_without_cancel`。

### 2.3 P2-1：去掉换行位置的临时 Vec

`Indexer::step` 改为直接迭代 `memchr::memchr_iter`，零额外分配、少一次遍历；行号 / CRLF 统计 / 锚点逻辑逐行保持等价。

### 2.4 P2-2（部分）：视图事件成对释放

`LargeView.dispose()`：`close()` + 遍历 `unlisteners` + `themeObserver.disconnect()`；
`LargeFileHost.dispose()` 转发并置空实例；只由 `releaseBackendResources()` 调用。

与 `close()` 分开的原因：`close()` 是「切标签」路径，事件订阅必须保留，否则切回来收不到索引进度与过滤批次。

## 3. 未修项与理由

| 项 | 不修理由 |
|---|---|
| P1-1 停手精算改增量 / 延后 | 报告的两种改法都会改变脏点时机：推迟到保存/切标签才精算，状态栏在「等长撤销回原状」时会持续显示脏；基于变更区间做增量需要缓存基线片段，与「不常驻全文」的目标冲突。属可观察行为变化，需单独立项并配 UI 验收 |
| P1-2 大文档变换不落整篇撤销栈 | 改 `history: false` 等于让大文档变换不可撤销（功能损失）；分块 diff 替换属于算法改造，回归面覆盖行操作 / 大小写 / 格式化 / 转换多个调用方，不宜与本次「不影响功能」的修复混做 |
| P1-3 草稿节流收敛 | 现状已是「防抖 + 空闲」两道节流；再收敛成「只记脏标记、退出前 flush」会把崩溃兜底从 1s 级降到退出级，属于可靠性取舍，需要单独评审 |
| P2-2 `SessionHost` / 其余单例观察器 | 报告自身结论是「当前不构成泄漏」；加 `dispose()` 需要新增生命周期接线，收益小于改动面 |
