# Git 源代码管理功能评估（2026-10-25）

> 问题：在侧栏加入 VS Code 风格的「源代码管理」（暂存的更改 / 更改）复杂吗？
> 结论基于当前代码事实：`commands/diff.rs` 已有 git 子进程封装与 `git_diff`；
> 侧栏已有可折叠分区框架；命令表为单一来源。

---

## 1. 结论（按范围分档）

| 范围 | 复杂度 | 预计 |
|---|---|---|
| **只读**：读取状态、展示「暂存的更改 / 更改」、点文件看差异 | 低 | 0.5–1 天 |
| **最小闭环**：只读 + 暂存 / 取消暂存 + 提交 | 中 | 1.5–2 天 |
| **完整常用**：再加放弃更改（discard）、刷新策略、错误提示 | 中偏高 | 3 天左右 |
| **VS Code 级**：分支切换、历史、冲突解决、多仓库、stash、子模块 | 高 | 不建议 |

---

## 2. 现有基础（为什么比从零做便宜）

1. `commands/diff.rs` 已有安全的 git 封装：`git(dir, args)` 用参数数组（不拼 shell），
   且 `git_diff(path, scope)` 已能产出「HEAD ↔ 工作区」与「HEAD ↔ 暂存区」的差异，
   直接可用于"点文件看 diff"。
2. 侧栏已有分区框架（`ui/sidebar.ts` + `panels/openEditorsView.ts` 的列表、右键、状态刷新模式），
   新增「源代码管理」分区是同类实现。
3. 命令注册表单一来源（`app/commandTable.ts`），新增命令自动进菜单 / 命令面板 / 快捷键 / 设置页。

---

## 3. 最小闭环的功能与拆分

| 能力 | 后端（新增 `commands/git.rs`） | 前端 |
|---|---|---|
| 读取状态 | `git_status(root)`：`git status --porcelain=v1 -z` → `{ branch, staged[], changes[], untracked[] }` | 侧栏分组列表（状态字母 + 数量 + 空态） |
| 查看差异 | 复用 `git_diff(path, "worktree" \| "index")` | 点击行 → 现有 diff 面板 |
| 暂存 | `git_stage(paths)`：`git add -- <paths>` | 行内按钮 / 右键 |
| 取消暂存 | `git_unstage(paths)`：`git restore --staged -- <paths>` | 行内按钮 / 右键 |
| 提交 | `git_commit(message)`：`git commit -m`，无暂存时拒绝 | 顶部输入框 + 提交按钮 |
| 放弃更改（v2） | `git_discard(paths)`：`git restore -- <paths>` | 右键 + 二次确认 + 重载标签 |
| 刷新 | — | 保存后 / 窗口聚焦 / 手动刷新（300ms 防抖） |

---

## 4. 必须处理的边界（决定"复杂不复杂"的部分）

1. **discard 是破坏性操作**：二次确认；已打开标签若脏，先阻止或先保存；完成后重载标签与文件树。
2. **路径解析**：`status -z` 用 NUL 分隔，避免中文 / 空格 / 引号转义；重命名（`R`）会带两个路径；未跟踪目录要按文件展开。
3. **性能**：超大仓库 `git status` 可能数百 ms 到数秒 → `spawn_blocking` + 防抖 + 结果上限；不要固定高频轮询。
4. **并发**：stage/unstage 与 status 并发会读到旧状态 → 前端串行队列（或后端 Mutex）。
5. **环境**：非 git 仓库、未安装 git、缺少 `user.name/email`（commit 失败要原样提示 stderr）。
6. **安全**：全部用参数数组；路径经 `PathGuard` 校验；不接受用户拼接的 git 选项。
7. **语义边界**：stage / unstage 不影响工作区文件，**不重载标签**；只有 discard / 分支切换才需要重载。

---

## 5. v1 不建议做

- 分支切换 / 创建、提交历史浏览、冲突解决（三方合并编辑器）
- 多仓库聚合、stash、子模块、LFS
- 用 `git2` crate 替代 CLI（体积与跨平台成本更高，CLI 更稳）

---

## 6. 建议

| 阶段 | 内容 | 理由 |
|---|---|---|
| v1 | 只读 + 暂存 / 取消暂存 + 提交 | 覆盖 90% 日常操作，无破坏性动作，风险低 |
| v2 | 放弃更改 + 更细的刷新策略 | discard 需要单独的确认与重载设计 |
| 不做 | 分支 / 历史 / 冲突 | 与"轻量文本编辑器"定位冲突 |

若要做，建议先出布局（分区列表 + 提交框）与验收清单，再实现；后端新增约 300–400 行、
前端侧栏分区约 250–350 行，测试以 `git_status` 解析（重命名 / 未跟踪 / 中文路径）为主。
