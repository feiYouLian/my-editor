# 点标签时文件树不定位的修复（2026-10-31）

## 现象

点击标签页切换文件时，如果左侧「文件」分区是收起的，目录树不会定位/高亮当前文件；
分区展开时则正常。

## 根因（两层）

1. **`revealPath` 只等一层加载**：子目录是懒加载的。原实现先展开祖先目录 → `render()`
   清空整棵树 → 然后只等「目标文件的父目录」那一层的 `pendingLoads`。
   但 `render()` 刚发起时，父目录这一层的加载任务还没注册（要等 root → 逐级加载），
   于是 `pending` 为 `undefined` → 立即 `selectRow()` → 此时行还不存在 → 选中落空。
2. **收起的分区里选中了也看不见**，而分区重新展开时没有任何补定位的动作。

## 修复

### FileTree（`src/panels/fileTree.ts`）

- 新增 `pendingReveal`：`revealPath` 先把目标记下来，再尝试选中。
- 新增 `tryReveal()`：找到行就选中 + `scrollIntoView`，找不到就保留目标。
- `loadChildren()` 的 `finally` 里调用 `tryReveal()`：每层目录渲染完成后重试一次，
  沿层级一路推进到叶子文件，不再依赖定时轮询（原来 20×50ms 的轮询在慢盘上会直接放弃）。
- `markSelected()` 会清空 `pendingReveal`：用户手动点了别的行，后续加载不能把选中抢回去。
- 新增 `canReveal(path)`：判断文件是否在当前工作区内（工作区外的文件在树里没有节点）。

### main.ts

| 场景 | 行为 |
| --- | --- |
| 侧栏可见 + 文件分区收起 | 先 `sidebarViews.switch("files")` 展开，再定位 |
| 侧栏整体隐藏（Ctrl+B） | 不强行弹出；重新显示侧栏时若文件分区是展开的，补一次定位 |
| 用户手动展开文件分区 | `sidebarViews.onChange("files")` 里补一次定位 |
| 文件不在当前工作区 | 不展开分区（树里没有对应节点） |
| 启动恢复会话期间 | `sidebarRestored` 守卫为 false，不自动展开，避免覆盖用户上次的收起状态 |

## 验证

```bash
npm test          # 77 passed
npx tsc --noEmit  # 通过
npm run build     # 通过
```

手工回归：

1. 收起「文件」分区 → 点不同标签：分区应自动展开并选中对应文件
2. 侧栏整体隐藏（Ctrl+B）→ 点标签 → 再 Ctrl+B 显示：应选中当前文件
3. 点在树里手动选中另一个文件 → 切标签后深层目录异步加载完成：选中应停在新标签的文件，不被抢回
4. 工作区外打开的文件：切过去不应把「文件」分区强行展开
