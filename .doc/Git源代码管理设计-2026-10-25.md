# Git 源代码管理 · 设计文档（2026-10-25）

> 范围：v1 最小闭环——**只读状态 + 暂存 / 取消暂存 + 提交**；v1.1 追加**分支切换 / 拉取**（状态栏入口）。
> 不做 discard / 历史 / 冲突。

## 1. 布局

侧栏新增「源代码管理」分区，位于最后（顺序：正在打开的文件 / 文件 / 搜索 / 大纲 / **源代码管理**）。

```
┌──────────────────────────────┐
│ ⌥ 源代码管理                › │  ← 分区标题（图标 + 名称 + 箭头）
├──────────────────────────────┤
│ main  ↑1 ↓0            [⟳]   │  ← 分支 / ahead-behind / 手动刷新
│ [提交信息________________][提交]│
│ ▼ 暂存的更改 (2)     [全部 −] │
│   M  src/app/a.ts         [−] │
│   A  src/app/b.ts         [−] │
│ ▼ 更改 (3)           [全部 +] │
│   M  src/panels/c.ts      [+] │
│   ?  src/notes.md         [+] │
│   R  old.ts → new.ts      [+] │
└──────────────────────────────┘
```

- 状态字母固定 2 字符宽：`M` 修改（黄）、`A` 新增（绿）、`D` 删除（红）、`R` 重命名（蓝）、`?` 未跟踪（灰）、`U` 冲突（红）。
- 未跟踪文件归入「更改」组（`?`）；重命名显示 `old → new`。
- 行点击 → 打开 diff：暂存组看「HEAD ↔ 暂存区」，更改组看「HEAD ↔ 工作区」。
- 组头可折叠；默认展开；无内容时组内显示「无」。
- 空态三种：非 Git 仓库（含原因）/ 没有更改 / 正在读取。

## 2. 操作

| 操作 | 入口 | 规则 |
|---|---|---|
| 刷新 | 分区展开、保存文件后、窗口聚焦、手动 `⟳` | 300ms 防抖；请求令牌丢弃过期结果；刷新中保留旧列表（不闪白） |
| 查看差异 | 点击文件行 | 不做内容读取上限判断（复用 `git_diff` 的 2MB 守卫） |
| 暂存 | 行 `[+]`、组头「全部 +」 | `git add -- <relative>`；重命名同时传旧/新路径 |
| 取消暂存 | 行 `[−]`、组头「全部 −」 | `git restore --staged --`，git < 2.23 回退 `git reset HEAD --` |
| 提交 | 输入框 + 按钮 / `Ctrl+Enter` | 消息 trim 非空；成功后清空输入并刷新；失败原样展示 stderr |
| 提交后 | — | 状态栏提示 `已提交 <short-hash>` |

- 提交按钮在暂存为空时禁用，并提示「暂存的更改为空」。
- 所有操作期间按钮 loading（禁用防重复），操作完成后统一刷新。

## 3. 后端设计（新增 `src-tauri/src/commands/git.rs`）

### 3.1 数据结构

```rust
#[derive(Serialize)]
pub struct GitFileEntry {
    /// 绝对路径（前端用于打开 diff）
    pub path: String,
    /// 相对仓库根，`/` 分隔（git 命令入参）
    pub relative: String,
    /// porcelain 状态字母（M/A/D/R/C/U/?）
    pub status: String,
    /// 重命名的旧相对路径
    pub orig_relative: Option<String>,
}

#[derive(Serialize)]
pub struct GitStatus {
    /// 仓库根（绝对路径；非仓库时为空）
    pub root: String,
    pub branch: String,
    pub ahead: u32,
    pub behind: u32,
    pub staged: Vec<GitFileEntry>,
    pub changes: Vec<GitFileEntry>,
    /// 非 git 仓库 / git 不可用原因（空串 = 正常）
    pub error: String,
    /// 条目超过上限被截断
    pub truncated: bool,
}
```

### 3.2 命令

| 命令 | 实现 | 说明 |
|---|---|---|
| `git_status(root)` | `rev-parse --show-toplevel` → `status --porcelain=v1 -z --untracked-files=all` → `symbolic-ref --short -q HEAD` → `rev-list --left-right --count HEAD...@{upstream}` | 全部 `spawn_blocking`；非仓库不抛 Err，写入 `error` 字段 |
| `git_stage(root, paths)` | `git add -- <relative paths>` | 路径逐个校验在仓库根内 |
| `git_unstage(root, paths)` | `git restore --staged -- <paths>`；失败回退 `git reset HEAD -- <paths>` | 同上 |
| `git_commit(root, message)` | `git commit -m <message>` → `rev-parse --short HEAD` | 消息 trim 非空 |

- **复用**：把 `diff.rs` 的 `git()` 辅助函数抽到 `git.rs`（`pub(crate)`），`diff.rs` 改为复用，避免两份子进程封装。
- **安全**：一律参数数组（`Command::new("git").args([...])`），禁止拼接 shell；路径经 `PathGuard.ensure_file_scope` 校验后转相对路径；不接受用户提供的 git 选项。
- **解析**：`status -z` 按 NUL 切分；`R`/`C` 条目后跟旧路径；状态字母取 `XY` 中非空格；未跟踪 `?`。
- **上限**：条目总数上限 5000，超出置 `truncated=true`。
- **错误**：git 不可用 / 非仓库 / 权限错误 → 返回 `Err(stderr)` 或 `error` 字段（状态查询用字段，操作用 Err）。

### 3.3 解析函数（可单测）

```rust
fn parse_status_z(output: &str) -> (Vec<GitFileEntry>, Vec<GitFileEntry>, bool)
```

- 纯函数，输入为 `git status --porcelain=v1 -z` 原始输出（测试用固定字符串，覆盖：修改、新增、删除、重命名、未跟踪、中文路径、超限截断）。
- 另加一个集成测试：临时目录 `git init` + 写文件，验证 `git_status` 端到端（git 不可用时跳过并打印原因）。

## 5. 边界与不做

| 项 | v1 决策 |
|---|---|
| 放弃更改（discard） | v1.2 已实现（文件级），见 §8；无组级「放弃全部」 |
| 分支创建 / 历史 / 冲突解决 | 不做（切换与拉取已在 v1.1 补上，见 §7） |
| 多仓库 / 子模块 / stash / LFS | 不做 |
| 未跟踪目录展开 | 用 `--untracked-files=all` 直接列文件 |
| 中文 / 空格 / 引号路径 | 由 `-z` + 参数数组覆盖，测试必须包含中文名 |
| 大仓库 | 结果上限 5000 + 防抖；不轮询 |
| 并发 | GitHost 串行队列：上一操作未完成时不发新的 status/stage 请求 |
| 编辑器状态 | stage / unstage / commit 不重载标签（不改变工作区文件） |

## 6. 验收

### 6.1 自动

```text
cargo test --lib commands::git   # 解析单测 + 临时仓库集成测试
npx tsc --noEmit
npm run build
```

解析单测覆盖：M / A / D / R / ? / 中文路径 / 超限截断 / 空输出。
集成测试覆盖：临时仓库 → 新文件（`?`）→ `git add`（staged `A`）→ 修改（changes `M`）→ `git_unstage` 回到 `?`。

### 6.2 手工

1. 打开 Git 仓库 → 分区显示分支与两组列表。
2. 修改文件并保存 → 分区自动出现 `M`（不需手动刷新）。
3. 点 `[+]` → 文件移入「暂存的更改」；点 `[−]` → 回到「更改」。
4. 组头「全部 +/−」→ 整组移动。
5. 提交信息 + 提交 → 列表清空、状态栏显示 short hash；暂存为空时提交被禁用。
6. 点文件行 → diff 面板：暂存组为「HEAD ↔ 暂存区」，更改组为「HEAD ↔ 工作区」。
7. 非 Git 目录 → 空态提示，不报错。
8. 中文 / 空格文件名 → 暂存、取消暂存、提交均正常。
9. 1000+ 更改的仓库 → 列表截断提示，滚动与操作不卡。
10. 提交时未配置 `user.name` → 状态栏原样展示 git 错误。

## 7. v1.1：状态栏分支入口（参考 VS Code）

### 7.1 布局

状态栏最左侧（路径之前）新增分区：

```
┌────────────────────────────────────────────────────────────┐
│ 〔⑂ main  ↓2↑1〕│ src/app/a.ts │ … │ 行 1，列 1 │ 共 120 行 │
└────────────────────────────────────────────────────────────┘
```

- 分支名（含图标）点击 → 分支切换面板；
- 右侧同步图标点击 → **同步（先拉取再推送）**；无领先/落后时显示 `⟳`，有则显示 `↓落后 ↑领先`，`behind > 0` 时用强调色；
- 非仓库 / 未打开工作区 / 读取失败 → 整块连同分隔符隐藏。

### 7.2 分支切换面板

复用命令面板的 `palette-*` 样式与键盘交互（与 `panels/quickOpen.ts` 同构）：

- 当前分支置顶并标注「当前」，其余按名称排序；
- 输入框模糊过滤（多关键词 AND）、`↑↓` 选择、`Enter` 切换、`Esc` 关闭；
- 当前分支再选中 = 关闭（不做无意义的 checkout）；
- 分支列表**每次打开现取**（外部终端改分支后立即反映）。

### 7.3 新增命令

| 命令 | 实现 | 说明 |
|---|---|---|
| `git_branches(root)` | `for-each-ref --format=%(HEAD)%09%(refname:short)%09%(upstream:track) refs/heads` | 纯函数 `parse_branches` 解析（含 `[ahead/behind]`、`[gone]`），当前分支置顶 |
| `git_checkout(root, branch)` | git ≥ 2.23 `switch <branch>`，否则回退 `checkout` | 分支名 `validate_branch` 校验（拒 `-` 开头、`..`、空白/控制字符）；工作区冲突由 git 拒绝并原样回传 stderr |
| `git_pull(root)` | 校验 `@{upstream}` → `pull --ff-only` | 只做快进：不生成合并提交、不弹编辑器；无上游给中文提示；`Already up to date` 归一为「已是最新」 |
| `git_push(root)` | 校验 `@{upstream}` → `push --porcelain` | 纯函数 `summarize_push` 解析 flag（快进 ` ` / 新增 `*` / 已最新 `=` / 被拒 `!`）并汇总为中文结果 |

- 网络类命令（pull / push）走 `git_net()`：置 `GIT_TERMINAL_PROMPT=0`，避免无 TTY 时卡在凭据输入；成功时合并 stdout + stderr（push 摘要走 stderr）。

### 7.4 切换 / 拉取后的编辑器同步

`gitHost.onWorkspaceChanged` → `reloadCleanTabs()`：

- 只重载**未编辑**（`!dirty`）的磁盘标签，脏标签保留现场（不默默覆盖未保存内容）；
- 被分支删除的文件重载失败 → 保留旧内容，仅清外部修改标记；
- 随后 `reloadActiveTab()` + `fileTree.refresh()` + `statusBar.refresh()`。

### 7.5 为什么拉取只做快进

`git pull` 默认可能产生合并提交并调用编辑器写 merge message，在无 TTY 的子进程里会挂住或失败。
`--ff-only` 保证：要么干净快进，要么如实报错，把合并/变基策略留给用户在自己的终端决定。
（后续如需对齐 VS Code 的 pull 策略，可读 `git config pull.rebase` 与 `pull.ff` 后再决定参数。）

## 8. v1.2：放弃更改（discard）

### 8.1 入口与提示

- 位置：文件行右键菜单，紧跟「暂存 / 取消暂存」之后，红色（`.context-menu-item.danger`）；
- 行内入口（v1.3）：行尾 `+` / `−` 左侧的撤回图标（悬停显示，红色 hover），点击与右键项同一动作 `onDiscard`；
- 文案：更改组为「放弃更改」，暂存组为「放弃更改（还原到 HEAD）」；
- 确认框（`confirmAction`，确认按钮为「放弃更改」）写明三件事：
  1. 影响目标（单文件相对路径 / N 个文件）；
  2. 还原基准（更改组 = 暂存区，暂存组 = 上次提交）；
  3. 未跟踪 / 新增文件会被删除（有则追加），并声明不可撤销。

### 8.2 后端：`git_discard(root, paths) -> usize`

不依赖前端传来的分组，逐个路径用 `git status --porcelain=v1 -z -- <rel>` 查真实状态后处理：

| 状态 | 处理 |
|---|---|
| `??`（未跟踪） | `git clean -f -- <rel>` 删除文件 |
| `X` 非空（已暂存） | 先 `unstage_one`（`restore --staged` → `reset HEAD` → 无提交时 `rm --cached`）；若为 `A`（新增）再 `clean -f` 删除 |
| 其余 | `git restore --worktree -- <rel>`（git < 2.23 回退 `checkout -- <rel>`） |

- 路径仍走 `safe_relative` + `PathGuard`，拒绝绝对路径与 `..`；
- 逐个执行：返回成功处理的条数，中途失败即中断并把 stderr 回传（已完成的不回滚，与 git CLI 行为一致）。

### 8.3 前端同步

成功后走 `onWorkspaceChanged` → `reloadCleanTabs()`：

- 未编辑标签重新读盘；
- **读盘失败（文件已被删除）不再静默**：保留内容并标记为「外部修改」，由用户决定重新载入或关闭。

### 8.4 为何不做组级「放弃全部」

组级一次删除多个未跟踪文件的风险与收益不对称（当前也没有多选），
先用文件级 + 明确的确认文案；若后续加多选，再按选中集合复用同一命令。

## 9. v1.3：失败弹窗与同步（pull + push）

### 9.1 为什么要弹窗

状态栏瞬时消息只有一行且 8 秒后消失；git 的失败原因往往多行且需要复制：

```
To github.com:user/repo.git
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'github.com:user/repo.git'
hint: Updates were rejected because the remote contains work that you do not
hint: have locally. ...
```

新增 `ui/dialogs.ts → showErrorDialog(title, detail)`：

- 标题（如「推送失败」）+ `<pre>` 原始输出（`white-space: pre-wrap`，限高 42vh 内部滚动）；
- 「复制详细信息」+「关闭」；`Esc` / `Enter` 关闭；背板点击关闭；
- 同一时刻只保留一个模态（失败可能密集触发）。

### 9.2 触发范围

`GitHost.act()` 统一处理（暂存 / 取消暂存 / 提交 / 放弃 / 切分支 / 拉取 / 推送 / 同步）：

| 通道 | 内容 |
|---|---|
| 状态栏 | `${label}失败：${首行}`（8s） |
| 弹窗 | `${label}失败` + 完整 stderr |
| console | `[git] ${label}失败` + 完整 stderr（便于开发者工具排查） |

读取状态（`git_status`）失败仍只走视图顶部提示，不弹窗——窗口聚焦 / 保存都会触发刷新，弹窗会变成噪声。

### 9.3 同步按钮

状态栏同步图标 = `sync()`：先 `git_pull`（快进），成功后再 `git_push`；任一步失败即中断并弹窗。
推送不改磁盘内容，因此不触发标签重载，只刷新状态。

菜单 / 命令面板另提供独立的「拉取」「推送」，供需要单独执行的场景使用。
