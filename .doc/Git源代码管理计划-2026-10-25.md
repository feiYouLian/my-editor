# Git 源代码管理 · 实施计划（2026-10-25）

> 设计见《Git源代码管理设计-2026-10-25.md》。
> 范围：v1 = 只读状态 + 暂存 / 取消暂存 + 提交；不含 discard / 分支 / 历史 / 冲突。
> 原则：后端先行、前端分两批接入、每批跑基线；不做破坏性操作。

---

## 1. 目标与验收口径

| 目标 | 验收 |
|---|---|
| 侧栏可见 Git 状态 | 分支、ahead/behind、暂存的更改、更改（含未跟踪） |
| 可暂存 / 取消暂存 | 行级与组级操作后列表即时刷新 |
| 可提交 | 消息非空 + 暂存非空；成功返回 short hash |
| 可看差异 | 点行打开 diff（暂存组 HEAD↔index，更改组 HEAD↔worktree） |
| 不伤数据 | v1 无任何工作区文件改写；命令失败只提示 |

## 3. 依赖与顺序

```
批次 1（后端命令）
   └─ 批次 2（只读 UI + 骨架）
        └─ 批次 3（操作 + diff + 刷新）
             └─ 批次 4（边界 + 文档）
```

- 批次 1 的解析函数先于命令完成（单测先行）。
- 批次 2 不依赖批次 3 的操作命令，可在后端就绪后并行推进 UI。
- 批次 3 的 `diffGitPath` 依赖现有 `git_diff`，不需要新后端命令。

## 4. 每批次固定动作

```text
npx tsc --noEmit
npm run build
cd src-tauri && cargo test --lib
```

外加：
1. 新增配置字段时 Rust `config.rs` 与前端 `settings.ts` 双端同步（本期只扩 `sidebarView` 联合类型，Rust 为 String，无需改结构）。
2. 新增 git 子进程一律参数数组；路径校验不得省略。
3. 每批结束时更新本文档的"进度记录"。

## 5. 风险与回滚

| 风险 | 处理 |
|---|---|
| `git status` 在大仓库慢 | `spawn_blocking` + 300ms 防抖 + 5000 条上限；不轮询 |
| 状态与操作并发导致列表回退 | GitHost 串行队列 + 请求令牌 |
| 中文 / 空格 / 重命名解析错误 | `-z` 解析 + 固定样例单测 + 临时仓库集成测试 |
| 非 Git 环境启动报错 | 状态查询用 `error` 字段而非 `Err`；空态展示 |
| 误操作导致数据损失 | v1 无 discard；stage/unstage/commit 均不改工作区文件 |
| 需要整体回滚 | 移除侧栏分区 + `view.sidebarGit` 命令 + `git.rs` 注册即可，其余模块无侵入 |

## 7. 明确不做（v1 冻结）

- 放弃更改（discard）—— v2 单独设计（二次确认 + 脏标签处理 + 重载）
- 分支切换 / 创建、提交历史、冲突解决、多仓库、stash、子模块、LFS
- 用 `git2` crate 替代 CLI
- 自动提交 / 自动 stage
