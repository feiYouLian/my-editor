# 编辑器正文可读性调整（2026-10-31）

> **后续结论：正文提亮被判定"太白"，已还原**（`darkBase` 删除、高对比度正文恢复原样）。
> 可读性问题改为从字体入手：新增 `layout.editorFontFamily` 设置项（空 = 默认等宽栈），
> 由用户按自己的机器选择渲染更清晰的等宽字体（如 `Consolas`）。
> 中文字体回退（`--font-mono` 中的雅黑 / 苹方）保留，它只影响 CJK 字形，不改变英文观感。

## 现象

纯文本 / Markdown 文件里，正文看起来发灰、不够白；中文偶尔发虚、笔画不清。

## 根因

1. **默认正文色偏灰**：深色主题用的是 one-dark，它的默认前景是 `#abb2bf`。
   代码文件里大面积的语法 token（关键字/字符串/注释各有颜色）会盖住这个问题，
   而 Markdown / 纯文本的正文几乎全是「默认色」，整屏扫过去就是灰的。
2. **等宽字体栈缺中文回退**：`--font-mono` 原本是
   `"Cascadia Code", "JetBrains Mono", Consolas, "Courier New", monospace`，
   这些字体都不含 CJK 字形，中文只能落回系统默认（Windows 上常见是宋体），
   在深色底 + 13px 下笔画会显得细而虚。Markdown 中文比例高，感受最明显。

## 修复

### 1. 正文提亮（`src/editor/theme.ts`）

- 深色：新增 `darkBase`，只覆盖默认正文色 `#abb2bf → #dfe3ea`，
  语法 token 继续用 one-dark 配色（注释该暗还是暗，层次不变）。
  选择器用 `& .cm-content`（特异性 0-2-0）压过 one-dark 的 `&`（0-1-0），
  **不依赖主题扩展的先后顺序**（CM6 多主题叠加的覆盖顺序容易踩坑）。
- 高对比度：`highContrastBase` 的正文显式设为 `#ffffff`（原来只设了背景，正文仍沿用 one-dark 的灰）。
- 浅色主题维持 `#1f2328`，不动。

### 2. 中文回退（`src/styles/main.css`）

```css
--font-mono: "Cascadia Code", "JetBrains Mono", Consolas, "Microsoft YaHei",
  "PingFang SC", "Source Han Sans SC", "Courier New", monospace;
```

中文走雅黑 / 苹方，英文仍走等宽字体。终端（xterm）同样受益。

## 备注

- 自定义主题（`themes/*.json` 的 `ui.foreground`）优先，不受本次默认值影响；
  觉得不够白可以直接改主题文件里的前景色。
- 字号在「设置 ▸ 页面布局 ▸ 字号（px）」可调（10–24，默认 13）。
  高 DPI（125% / 150% 缩放）下 13px 会被放大到非整数像素，调成 14 或 16 会更锐利。
- 没有加 `-webkit-font-smoothing: antialiased`：在 Windows 上它是去掉次像素渲染，
  字会**更细**，与本诉求相反。

## 最终默认值（对齐 VSCode）

VSCode 的 `EDITOR_FONT_DEFAULTS`：Windows `Consolas, 'Courier New', monospace` / 14px，
macOS `Menlo, Monaco, ...` / 12px。据此把默认值改成同一套：

- `--font-mono` → `Consolas, Menlo, Monaco, "Cascadia Code", "JetBrains Mono", 中文回退, monospace`
  （Windows 命中 Consolas，macOS 命中 Menlo；Cascadia Code 后移，它在小字号深色底上偏细）
- `layout.editorFontSize` 默认 `13 → 14`（前端 `defaultConfig` 与 Rust `LayoutSettings::default` 同步）
- `layout.editorFontFamily` 仍为空 = 用上面的栈，可按机器覆盖

注意：这两个默认值只影响**新配置**。已有 `config.json` 里写过
`"editorFontSize": 13` 的用户不会自动变成 14，需要在「设置 ▸ 页面布局」里改一次。
