# 未命名草稿「副本」、标签合并与光标位置丢失修复（2026-10-31）

## 问题 1：未保存的新建文件，重启后变成「xxx（副本）」

### 根因

`Tab.path` 声明为 `string | null`，但 `tabStore.open()` 直接写 `content.path`，而未命名文档的
`FileContent.path` 是空串 `""`。于是：

1. `write_draft` 收到 `path: Some("")`；
2. Rust 侧 `fingerprint("")` 得到 `(mtime=0, size=0, hash="")`；
3. `is_stale` 判断 `mtime == 0 && size == 0` → **原文件已不存在 → 过期**；
4. 恢复流程对过期草稿走「新建未命名文档 + 名字加（副本）」分支。

空串与「没有关联文件」在语义上不是一回事，但代码里被混用了。

### 修复（三处归一）

| 位置 | 改动 |
| --- | --- |
| `src/store/tabs.ts` `open()` | `path: content.path \|\| null` |
| `src/app/sessionHost.ts` `persistDraft` | `path: tab.path \|\| null`（防其它路径漏网） |
| `src-tauri/src/commands/session.rs` `write_draft` | `draft.path.filter(|p| !p.is_empty())` |
| `src-tauri/src/commands/session.rs` `is_stale` | 空串按「无关联文件」处理（兼容已存在的旧草稿） |

## 问题 2：两个标签「变一个」

两个独立成因，都已修：

1. **同名未命名标签**：草稿恢复时沿用上次的标签名，若该名字已被占用，会出现两个同名标签，
   在标签栏里无法区分。`fileService.newUntitled(name)` 现在检测重名并改用空闲序号。
2. **草稿 key 冲突导致草稿被删**：新标签 id 是进程内自增（`tab-${++seq}`），重启后从 `tab-1`
   重新开始，而未命名草稿的 key 正是 `untitled:${tabId}`。
   原实现「先 `void persistDraft(newId)` 再 `await deleteDraft(oldKey)`」，当两个 id 相同时，
   刚写好的草稿会被随后执行的删除抹掉，反复重启后草稿数量/内容漂移。
   现在改为**先删旧草稿、再写新草稿**。

## 问题 3：重新打开后光标回到文件顶部

### 根因

启动恢复的顺序是「会话恢复（含光标）→ 草稿自动恢复」。草稿恢复对激活标签调用了
`onReloadActiveTab()`（把 `tab.content` 重新送进编辑器），而 `loadDocument` 会让选区归零；
此时会话光标早已在首次载入时被消费（`restoredCursors.delete`），不会再应用一次。

### 修复

- `SessionHost` 增加 `sessionCursors` 备份（`primeRestoredCursors` 时同时写入），
  新增 `replayRestoredCursor(tab)`；
- `bootstrap()` 最后按「切换过标签 或 恢复过草稿」的条件 `await tabSwitcher.load()`，
  再 `replayRestoredCursor(选中标签)`，把关闭时的行列放回去。

## 顺带补齐：选中未命名标签的恢复

未命名标签没有路径，不进 `openFiles`。之前如果关闭时选中的是未命名标签，重启后会选中第一个文件标签。

- `SessionState` 新增 `activeUntitledName`（Rust `active_untitled_name`，`#[serde(default)]` 兼容旧会话）
- `buildSessionState()` 在激活标签无路径时记录其名称
- `autoRestoreDrafts(activeName)` 返回 `{ restored, activeTabId }`，匹配到同名草稿时把它作为最终激活项

## 追加（同日）：滚动位置精确恢复

### 现象

在文件最底部关闭，重启后视图会上移一点，定位不准。

### 根因

会话只记了光标行列，恢复时用 `scrollIntoView` —— 那是「让光标刚好可见」，
不等于关闭时的滚动位置（底部时视口与光标行不是一回事，且 CM6 会留出边距）。

### 修复

`SessionFile` 新增 `scrollTop`（Rust `Option<f64>`，旧会话缺省走原逻辑）：

1. **写盘**：`buildSessionState` 对激活标签实时读 `view.scrollDOM.scrollTop`
   （纯滚动不动光标，只有写盘这一刻拿得到真实值）；其它标签用 `scrollMemory`；
   尚未载入过的标签回退到 `restoredCursors`，避免启动后 400ms 的结构帧写盘把位置覆盖成默认值。
2. **切换**：`TabSwitcher.load()` 在切走前 `captureScroll(旧标签)`（编辑器只有一个滚动容器，
   `loadDocument` 后旧标签的位置就读不到了），载入后 `restoreScroll(新标签)`。
3. **恢复**：`applyCursor` 不再用 `scrollIntoView`，改为 `view.requestMeasure(...)` 的
   write 阶段写 `scrollDOM.scrollTop`（等布局测量完成，否则高度未算完会被夹紧）。

**没有用 scroll 事件监听**：切标签时 `loadDocument` 会把滚动清零，监听器会把 0 当成
用户位置写回去，反而更不准（也会让「切走再切回」丢失位置）。

### 附带修复

同一处兜底解决了"会话恢复期间写盘覆盖未载入标签位置"的旧问题：
pending 标签在首次激活前，line/col/scrollTop 都取会话原值，不再被写成 1/1。
