## 2. 本轮改动

### 2.1 N1（P0）· 取消过滤后不留半截结果

两侧都改，缺一不可：

- **Rust**（`large.rs`）：新增 `finalize_matches(cancelled, matches, pending)`，取消时清空两个集合。末批 `FilterBatch.matches` 与命令返回值 `FilterResult.matches` 都不再带出已扫描的部分命中。`FilterProgress.matches` 也随之为 0。
- **前端**（`largeView.ts`）：
  - `applyFilterBatch`：`p.cancelled` 判断**提到 `matchBuf.append` 之前**，命中 `finishCancelled`。
  - `runFilter`：`res.cancelled` 判断提到 `matchBuf.replace` 之前。
  - 新增 `finishCancelled(requestId)`：幂等收尾——`matchBuf.reset()`、清 cache、恢复全文视图、提示「过滤已中止，已恢复显示全部行」；同时设置 `filterFinishedId`，迟到批次不会再追加。

为什么两条到达顺序都要处理：末批事件与命令返回谁先到不确定，原实现两条路径都是「先消费结果、后判断取消」，谁先到都会留下部分命中。

### 2.2 N4（P2）· 窗口读取不再克隆整张锚点表

`read_large_lines` 原来把 `entry.anchors.clone()` 带出锁再 `locate`。1GB / 64KB 锚点约 16K 项 ≈ 256KB，滚动时每次窗口读取都要分配一次。改为**在锁内 `locate`**，只带出 `(byte_offset, line_no)` 两个标量。

### 2.3 N5（P2）· 过滤块缓冲复用

原来每块 `let mut data = take(carry); extend_from_slice(4MB)` 与 `carry = data[cut..].to_vec()` 各产生一次拷贝。改为跨块复用同一个 `Vec<u8>`：每块 `extend` 后处理完整行前缀，再 `drain(..cut)` 移除已处理部分。平稳态零新分配（超长跨块行除外）。

抽出 `append_block(data, block) -> cut` 便于单测，覆盖「跨块半行补齐」与「整块无换行继续累积」两个边界。
