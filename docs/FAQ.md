# 常见问题

按「现象 → 原因 → 怎么做」组织。操作细节见 [`USER-GUIDE.md`](./USER-GUIDE.md)。

---

## 1 打开中文文件是乱码

**原因**：文件不是 UTF-8（常见于 GBK / GB18030 / Big5）。编辑器按 UTF-8 优先探测，探测失败时会退回一个猜测。

**怎么做**：

1. 看状态栏的**编码**字段——疑似乱码时它后面会有 `⚠`，鼠标悬停能看到原因和建议编码
2. 点它 → 选「重新打开为 → GBK」（或提示的编码）。这只改变**内存里的解读方式，不写盘**
3. 确认内容正确后再 `Ctrl+S`，此时才会按新编码真正转码保存
4. 如果保存前想确认，用「另存为指定编码…」生成副本

**为什么不做全自动**：猜错编码自动保存会破坏文件，所以只建议、不擅自改。

---

## 2 为什么我的 `.log` 文件打开是只读的

**原因**：`.log` 扩展名一律进入**只读大文件虚拟视图**（无论大小），因为它通常意味着体积大、只看不改。

**怎么做**：

- 只想看：直接用，虚拟视图支持过滤、Minimap、编码重解释，滚动比编辑器更省内存
- 真要改：视图里有「以编辑器打开」逃生门，会全量载入（GB 级文件可能失败或卡住，界面会警告）
- 想取消这个规则：设置里改 `largeFile.logExtensions`（例如清空该数组）

---

## 3 内存占用 260 MB 以上，这也叫「轻量」？

**是的，但「轻量」指的是包体和启动，不是内存。**

拆开看（实测数据见 README「资源占用」一节）：

| 组成 | 私有内存 |
| --- | --- |
| 应用自身（Rust 后端 + 业务逻辑） | **约 5.8 MB** |
| WebView2 进程组（系统渲染引擎） | 约 262 MB |

编辑器界面跑在系统的 WebView2（Chromium）里，这个引擎的固定开销与业务代码无关——即使一个功能都不写，也是这个量级。同类方案里 Electron 更高，Tauri 省掉的是 Node 运行时与包体，**省不掉渲染引擎**。

所以：安装包 3 MB、启动 50 ms 是真实的；「省内存」不是。如果目标机器内存极紧张，需要的是原生渲染的编辑器（如 Notepad++ / Sublime），而不是本项目。

---

## 4 切回某个标签后 `Ctrl+Z` 没反应

**原因**：撤销历史按标签缓存，有两条硬边界——**单文档超过 2 MB**，或**同时缓存的标签超过 8 个**（超出时淘汰最久未用的）。被淘汰的标签切回来时撤销栈已释放。

**怎么知道是不是这个原因**：切回时状态栏会提示「该标签的撤销历史已释放（文档过大或打开标签过多）」。

**怎么办**：

- 立即需要撤销：先别切标签
- 习惯性多开大文件：减少同时打开的大文件数量，或用「关闭其他」收敛
- 已经丢了的编辑：看 `drafts/` 里的草稿、或用 Git 的改动对比找回最近保存版本

---

## 5 文件被别的程序改了，提示在哪

三种可见位置：

1. **标签上的 `⟳`**：即使是被压在后面的标签也会显示
2. **通知中心**（状态栏 `⚠ N`）：包含文件名，点「处理」可切到该标签（若当前不是它，会提示先切换）
3. **切到该标签时**：弹窗给三选「重新加载 / 与磁盘比较 / 取消」

默认**不在后台打扰**：只有你切到那个标签时才会弹窗。自己保存不会误触发（内部有写入标记）。

---

## 6 误关了标签，内容还能找回吗

**能，但有条件。**

- 未保存的编辑会自动写入 `drafts/`（防抖，不是每次按键都写）
- 重新打开同一个文件时，若草稿比磁盘新，会提示恢复
- 启动时会统一列出可恢复的草稿供勾选
- 批量关闭（关闭左侧/右侧/其他/全部）前也会先落草稿，确认框里会说明这一点

**恢复不了的情况**：草稿保留天数已过（设置项 `session.draftRetentionDays`）、内容从未变脏、或磁盘上文件被删且草稿也被清理。

---

## 7 终端打不开 / 一闪就失败

按顺序排查：

1. **看状态栏消息**：终端启动失败会显示首行原因（如 shell 路径不存在）
2. **`.log` 之外最常见的原因是 shell 配置**：设置项 `terminal.shell` 指定的程序不存在。清空该项会回退到 PowerShell（有 `pwsh` 时优先）
3. **`cmd.exe` 不支持「在终端运行当前文件」**：请改用 PowerShell
4. **终端不是沙箱**：里面能执行任意命令，也不受 Code Run 的 30 秒 / 1 MB 限制

---

## 8 格式化失败

**看错误弹窗的第一行**——通常是「没有安装对应的格式化工具」。本项目有两条格式化通道：

| 语言 | 通道 | 需要什么 |
| --- | --- | --- |
| JS/TS/JSX/TSX/JSON/CSS/Markdown/HTML/YAML | 内置 Prettier（懒加载） | 不需要额外安装 |
| SQL / XML | 内置格式化器 | 不需要额外安装 |
| Python / Go / Rust / Java / C++ | 调用系统 CLI | 需要 `black` / `gofmt` / `rustfmt` / `google-java-format` / `clang-format` |

失败详情（含安装提示）在弹窗里可「复制详细信息」，也会进通知中心。超过 10 000 行的文档会先确认再格式化。

## 9 `git push` / `git pull` 失败，提示认证问题

**原因**：本应用调用系统 `git` 命令，但**禁用了交互式凭据提示**（否则会在后台卡死）。

**怎么做**：在系统终端里进入仓库目录，手动执行一次 `git push`（或 `git pull`），按提示完成账号 / token 认证。Git 凭据助手会记住，之后回来用应用内的按钮即可。

其他常见失败：本地有未提交改动导致拉取冲突、远端分支不存在、SSH key 未加载。弹窗里有完整 stderr 可复制。

---

## 10 删除的文件去哪了？能还原吗

删除会**移入系统回收站**（Windows 回收站 / macOS 废纸篓），不是永久删除。

- 还原：从系统回收站直接还原
- 目录删除：整个目录一起进回收站（包括子内容）
- 注意：回收站不会自动清理，大目录删除后磁盘空间不会立刻释放，需要清空回收站

---

## 11 改了快捷键，不生效

1. **固定键位不能改**：撤销、删行、移动行、复制行、折叠、书签等标为「固定」的项只展示不可改绑（它们是编辑器内核行为）
2. **冲突检测**：录制时若与已有键位冲突会提示，需要先解绑原项
3. **保存后生效**：改完在设置页确认，配置写回 `config.json`；写入失败会在状态栏提示「重启后可能不会保留」
4. **系统级占用**：某些组合被系统或其它软件占用（如输入法、显卡驱动热键），应用收不到

---

## 12 换电脑了，怎么把环境搬过去

把应用配置目录（「设置 → 关于」里可复制路径）整个拷到新机器同位置即可：

- 必须：`config.json`（设置 + 键位）、`workspace.json`（工作区根目录与展开状态）
- 可选：`session.json`（上次打开的文件）、`drafts/`（未保存草稿）、`replace-history/`（替换历史）

注意 `config.json` 里可能存着绝对路径（如工作区根目录），换机器后路径不存在时相关面板会空着，重新打开目录即可。

---

## 13 安装包只有 3 MB，为什么第一次启动要等一小会儿

安装包小是因为不含浏览器内核，界面跑在系统自带的 **WebView2** 上。第一次启动时若系统尚需初始化 WebView2（或 Windows 10 上首次安装运行时），会明显慢于后续启动。

- 后续冷启动：窗口出现约 50 ms 量级（实测见 README）
- 首次启动：取决于 WebView2 运行时是否就绪

## 14 大文件为什么不让编辑

**门槛**：≥ 20 MB 或 `.log` 的文件默认进入只读虚拟视图。

**原因**：编辑器内核需要持有全文（文本 + 语法树 + 撤销历史，约为文本的 2–3 倍）。一个 500 MB 的文件进编辑器会直接吃掉 1 GB 以上内存并卡死。

**替代方案**：

- 看：虚拟视图（过滤、跳转、Minimap）
- 改一小段：先 `Ctrl+A` 复制到新文档改，或用命令行工具（`sed` / `awk` / PowerShell）
- 必须改：视图里的「以编辑器打开」逃生门，但要知道风险

## 15 怎么确认「启动变慢了」是不是真的

打开应用配置目录里的 `startup.json`：

```json
{"processToFrontendReadyMs":412,"recordedAtUnixMs":1761600000000}
```

`processToFrontendReadyMs` = 进程启动到界面可交互（首帧已绘制）的毫秒数。**每次启动覆盖写，只保留最近一次**，不是日志。

对比口径要注意：这个数字包含 WebView2 初始化，比 README 里「窗口出现 48–53 ms」大一个量级，两者不是一回事。

## 16 双击图标好像开了两个窗口 / 第二个没反应

应用是**单实例**的：第二次启动会把已有窗口拉到前台（取消最小化、显示、聚焦）然后自身退出。

所以看到「没反应」通常是已有窗口被拉到了前面。如果窗口确实不见了，检查是否在其它虚拟桌面或被移出屏幕。

---

## 17 提示一闪就没了，没看清

点状态栏那条消息文字本身（显示期间），或「视图 → 最近消息…」，可以回看**最近 20 条**状态消息（内存态，重启清空）。

需要长期处理的失败（保存失败、Git 失败、格式化失败、外部修改）会进**通知中心**（状态栏 `⚠ N`），那里的条目带操作按钮，不会自动消失。

---

## 18 刚放弃了 Git 更改，还能找回吗

**能，但要手动翻文件**（应用内没有一键还原）。

放弃操作虽然仍不可撤销，但覆盖 / 删除前已经把工作区内容复制到配置目录：

```
<配置目录>/discard-backup/<时间戳>/<原相对路径>
<配置目录>/discard-backup/<时间戳>/manifest.json
```

- 按原目录结构存放，直接打开复制回来即可
- `manifest.json` 记录仓库根、时间、文件清单
- 保留最近 10 次，更早的自动清理
- 单文件超过 8 MB 或单次总量超过 32 MB 的部分不会备份，放弃成功的提示里会说明「N 个过大文件未备份」

配置目录路径可在「设置 → 关于」里复制，或点「打开配置目录」。

---

## 19 我想反映一个 bug，需要提供什么

信息越具体越好：

1. 复现步骤（从哪个操作开始）
2. 通知中心 / 最近消息里相关的文案（可直接选中复制）
3. 失败操作的错误弹窗内容（点「复制详细信息」）
4. `startup.json` 的内容（判断是否与启动状态有关）
5. 版本号（设置 → 关于）

> 应用**没有**内置日志文件，所以上述复制内容是唯一可留档的证据，请在重启前保存。
